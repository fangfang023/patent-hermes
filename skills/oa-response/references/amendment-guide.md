## 修改原则

### 最高原则：不得超范围

> 《专利法》第33条：申请人可以对其专利申请文件进行修改，但是对发明和实用新型专利申请文件的修改不得超出原说明书和权利要求书记载的范围。

**"记载的范围"包括**：
- 原说明书明确记载的内容
- 原权利要求书明确记载的内容
- 从原申请文件中直接、毫无疑义地确定的内容

**禁止的修改**：
- 将原申请文件中的"优选"内容改为"必须"
- 将具体数值推广为更宽的范围
- 补充原申请文件未提及的技术特征
- 改变原申请文件中的技术含义

## 修改策略

### OA 答复修改规则（优先于下述策略）

> **重要**：以下规则仅在答复审查意见通知书时适用，优先于本文件中的通用修改策略。

#### 修改类型判定流程

```
收到审查意见
  │
  ├─ 审查意见指出：独权不具备新颖性/创造性
  │    → ✅ 允许：合并从属权利要求到独权（策略1）
  │    → ✅ 允许：从说明书中增加限定特征到独权（策略2，需说明书记载）
  │    → ❌ 禁止：新增从属权利要求
  │
  ├─ 审查意见指出：权利要求不清楚/术语有歧义
  │    → ✅ 允许：修改表述（策略4，仅形式修改）
  │    → ❌ 禁止：借修改表述之机增加新限定
  │
  ├─ 审查意见指出：权利要求得不到说明书支持
  │    → ✅ 允许：缩小权利要求范围以匹配说明书
  │    → ❌ 禁止：修改说明书以扩大描述范围
  │
  └─ 其他情况
       → 默认：只能合并从权到独权，或修改形式缺陷
```

#### OA 答复中的说明书修改限制

| 修改类型 | 是否允许 | 示例 |
|---------|---------|------|
| 修正笔误/编号错误 | ✅ | "第0035段"改为"第0036段" |
| 统一术语 | ✅ | "模块A"统一改为"处理模块A" |
| 新增实施例 | ❌ | 不可在说明书中增加新的实施方式 |
| 修改技术方案描述 | ❌ | 不可改变发明内容中的技术方案描述 |
| 新增附图 | ❌ | 不可增加新的附图 |

### 策略1：合并权利要求

**适用场景**：独立权利要求被指出不具备新颖性/创造性

**方法**：将从属权利要求的附加技术特征并入独立权利要求

```markdown
修改前：
  权利要求1：一种方法，包括步骤A和B。
  权利要求2：根据权利要求1所述的方法，还包括步骤C。
  权利要求3：根据权利要求1所述的方法，步骤A采用X算法。

修改后（合并权2+权3到权1）：
  权利要求1：一种方法，包括步骤A和B，其中步骤A采用X算法，还包括步骤C。
  权利要求2：（原权4，调整为引用新的权1）
```

**注意**：
- 合并后的独立权利要求需要重新检查引用关系
- 被合并的从属权利要求编号需要删除或调整
- 需要从说明书中找到合并特征的支撑依据

### 策略2：增加限定特征

**适用场景**：权利要求概括过宽，被指出不具备创造性或得不到说明书支持

**方法**：从说明书中提取技术特征，增加对权利要求的限定

```markdown
修改前：
  权利要求1：...基于相似度计算...

修改后（增加具体限定）：
  权利要求1：...基于余弦相似度计算，相似度阈值范围为0.7-0.95...
```

### 策略3：删除权利要求

**适用场景**：某些权利要求确实无法克服审查意见

**方法**：直接删除该权利要求，调整后续编号

```markdown
修改前：
  权利要求1-10

修改后（删除权3、权7）：
  权利要求1-8（重新编号）
```

### 策略4：修改表述

**适用场景**：权利要求不清楚、术语有歧义

**方法**：使用说明书中更明确的表述替换

```markdown
修改前：
  ...适当的参数...

修改后：
  ...参数α，取值范围为0.01-0.1...
```

## 修改后编号调整规则

```python
# 编号调整算法
原权利要求列表 = [权1, 权2, 权3, 权4, 权5, 权6, 权7, 权8]
删除列表 = [权3, 权7]  # 被删除或被合并的权利要求
保留列表 = [权1, 权2, 权4, 权5, 权6, 权8]

# 重新编号
新编号映射 = {
  权1 -> 新权1,
  权2 -> 新权2,
  权4 -> 新权3,
  权5 -> 新权4,
  权6 -> 新权5,
  权8 -> 新权6
}

# 更新所有从属权利要求的引用编号
FOR 每条保留的权利要求:
  IF 该权利要求引用了被重新编号的权利要求 THEN
    更新引用编号 = 新编号映射[原引用编号]
  END IF
END FOR
```

## 修改对照表格式规范

CNIPA 要求申请人提交修改时标明修改内容。对照表用于清晰展示每处修改，单独成文件。

### 格式要求

1. **每处修改单独一行**，同一权利要求的多处修改用不同序号区分
2. **修改前/后必须写原文**，不允许写"略"或"同上"
3. **所有权利要求都列出**，未修改的标注"无修改"
4. **修改依据必须引用说明书段落号**，不允许留空

### 标准格式

```markdown
## 权利要求书修改对照表

本次修改共涉及 [N] 处，涉及 [M] 条权利要求。

| 序号 | 权利要求 | 修改位置 | 修改前（原文） | 修改后（新文） | 修改依据 |
|------|---------|---------|--------------|--------------|---------|
| 1 | 权利要求1 | "基于相似度计算"处 | 基于相似度计算 | 基于余弦相似度计算，相似度阈值范围为0.7-0.95 | 说明书第[0035]段 |
| 2 | 权利要求3（原） | 整条 | （整条内容） | （已删除，并入权利要求1） | — |
| 3 | 权利要求3（新，原权4） | 引用关系 | 根据权利要求3 | 根据权利要求1 | 因原权3删除，调整引用 |
| — | 权利要求2 | — | （无修改） | （无修改） | — |

### 修改不超范围声明

以上所有修改均在原说明书和权利要求书记载范围内。
```

### 常见错误

| 错误 | 正确做法 |
|------|---------|
| 同一条权利要求的多处修改合并为一行 | 每处修改单独一行，用不同的序号 |
| 修改前/后写"略"或"同上" | 必须写出原文 |
| 只列出修改的权利要求，未修改的不列 | 所有权利要求都列出，未修改标注"无修改" |
| 修改依据留空 | 必须引用说明书段落号 |

## 修改检查清单

完成修改后，对照 SKILL.md 中的「质量检查」清单逐项检查。修改阶段需特别关注：

- 每处修改是否能在原说明书或权利要求书中找到依据
- 修改对照表与实际修改是否一致
- 删除的权利要求是否在其他权利要求中有保留（避免保护范围不必要的缩小）
