# 中国发明专利申请文件撰写

以资深专利工程师视角，基于输入信息撰写全套专利申请文件。先权利要求书确定保护范围，再说明书展开实施细节。

## 输入模式

本 Skill 支持两种输入模式，根据输入内容自动判断：

| 模式 | 触发条件 | 执行范围 |
|------|---------|---------|
| **A. 标准模式** | 输入为交底书/技术方案（无预写权利要求书） | 从阶段1开始完整执行 |
| **B. 基于已确认权利要求书** | 输入包含"已确认的权利要求书"或权利要求书文件路径 | **跳过阶段1和阶段1.5**，直接从阶段2（说明书）开始 |

**模式判断方法**：检查 prompt 中是否包含权利要求书文件路径（如 `./generated_docs/权利要求书_*.md`）或明确说明"已确认的权利要求书"。如果包含，进入模式 B；否则进入模式 A。

**模式 B 的输入要求**：必须同时提供：
1. 已确认的权利要求书文件路径
2. 原始交底书或技术方案（用于说明书展开的素材来源）

---

## 输入验证

必须包含：技术领域（细分）、现有技术缺陷（3-5项）、核心技术手段（原理+方式+参数）、预期效果（优势+可验证）。若任一项无法明确，需先补充技术描述。

## 输出规则

**所有最终交付文件必须为 .docx 格式。** .md 仅作为撰写中间产物。

输出目录：`./generated_docs/`

全套3个文件，总计≥15000汉字：

| # | 最终文件名 | 内容 |
|---|----------|------|
| 1 | `权利要求书_[发明名称].docx` | 独立权利要求2-3条 + 从属权利要求8-12条，≥3000汉字 |
| 2 | `说明书_[发明名称].docx` | 技术领域、背景技术、发明内容、具体实施方式、附图说明，≥8000汉字 |
| 3 | `摘要与附图说明_[发明名称].docx` | 摘要（200-300字）、说明书附图清单（图号+图名）、摘要附图指定、附图标记说明 |

输出格式详见 [references/template.md](references/template.md)。

## 阶段执行纪律

**严格按阶段顺序执行，每个阶段独立完成后才能进入下一阶段。**

1. **写完即存**：每个阶段完成后，立即将结果写入 .md 文件
2. **从文件读取**：下一阶段需要上一阶段的输出时，从已写入的 .md 文件中读取，而非依赖 context 中的记忆
3. **逐阶段读取 references**：只读取当前阶段所需的 reference 文件，不要一次全部加载
4. **docx 转换逐个执行**：阶段5中每个文件独立转换，完成一个再转下一个

这样确保 context 不会被前面阶段生成的内容撑满，每个阶段都有充足的 context 空间。

## 撰写工作流

**阶段1：权利要求书**（**模式 B 时跳过此阶段**）

> **条件执行**：如果输入中包含已确认的权利要求书文件路径（模式 B），则跳过阶段1和阶段1.5，直接进入阶段2。跳过时须从文件读取权利要求书内容，确保后续阶段可引用。
- 【必须】读取 `patent-claims-writing` Skill 的 [references/claims-guide.md](../patent-claims-writing/references/claims-guide.md) 了解权利要求书撰写规范
- 基于输入信息中的核心技术手段，提取技术特征
- 撰写独立权利要求（前序部分+特征部分，禁止功能性限定）
- 撰写从属权利要求（细化结构、限定参数、优选方式）
- **写入文件**：`./generated_docs/权利要求书_[发明名称].md`

**阶段1.5：权利要求书自检与修正**（**模式 B 时跳过此阶段**）

权利要求书写入后、说明书展开前的强制检查点。**自检未通过必须修正并重新写入，最多重试2次（总计3轮检查）。**

- 【必须】读取 [references/claims-self-check.md](references/claims-self-check.md) 获取完整的7项检查清单、判定标准和修正示例
- 从文件重新读取权利要求书（不依赖 context 记忆），切换为审查员角色
- 逐条执行7项检查：①必要技术特征 ②独立权过窄 ③功能性限定 ④防御纵深 ⑤术语一致性 ⑥从属权关联性 ⑦权利要求数量
- 有未通过项则修正后重新写入文件，再次检查；最多3轮
- **【必须输出】自检结果摘要表**（格式见 claims-self-check.md）

**阶段2：说明书**

> **模式 B 注意**：此时权利要求书已在阶段1之前由外部确认并写入文件。从 `./generated_docs/权利要求书_[发明名称].md` 读取已确认的权利要求书，作为说明书展开的唯一基础。

### 2.0 说明书撰写红线（必须遵守）

说明书是专利申请的法律文件，不是交底书的改写。以下规则在整个阶段2中强制执行：

1. **禁止照抄输入文档**：说明书各章节必须以专利申请的正式语言重新撰写，不得直接复制交底书、重述文档或其他输入文档的原文段落。如果发现某段表述与输入文档高度相似，必须用专利语言重新表述。
2. **背景技术独立分析**：背景技术章节需要进行独立的现有技术分析，描述3-5种相关现有技术的原理、流程、特点和局限，不能照抄交底书中"现有技术"部分的原文。
3. **多实施例展开**：具体实施方式必须基于权利要求书中的技术特征，构造至少2-3个**不同应用场景**的具体实施例（例如：不同行业场景、不同硬件配置、不同参数范围），不能只复述交底书中的那一个方案。每个实施例应有独立的硬件配置、软件参数和操作步骤。
4. **说明书与交底书的语言差异**：交底书是内部技术沟通文档（描述"做了什么"），说明书是法律文件（必须详述"怎么做、为什么这么做、效果如何"），语言风格和深度完全不同。

### 2.1 执行步骤

- 从 `./generated_docs/权利要求书_[发明名称].md` 读取权利要求书中的技术特征，作为说明书展开的基础
- 【必须】读取 [references/writing-guide.md](references/writing-guide.md) 的"CNIPA 审查指南核心要点"、"说明书与交底书的本质区别"和各章节撰写要求
- 【必须】读取 [references/implementation-examples.md](references/implementation-examples.md) 的"实施例构造方法论"和实施例模板
- 撰写技术领域、背景技术、发明内容、具体实施方式、附图说明（撰写过程中直接遵守2.0红线，不要先抄再改）
- **写入文件**：`./generated_docs/说明书_[发明名称].md`

**阶段3：摘要与附图说明**
- 从 `./generated_docs/说明书_[发明名称].md` 读取发明内容章节和附图说明章节
- 【按需】读取 [references/template.md](references/template.md) 的"摘要与附图说明合并文档模板"章节
- 【按需】读取 [references/mermaid-examples.md](references/mermaid-examples.md) 参考绘制方法
- 生成内容必须包含四个章节：①摘要（300字以内）②说明书附图清单（声明附图总数+每张图号图名）③摘要附图指定④附图说明（逐图标记说明）
- **写入文件**：`./generated_docs/摘要与附图说明_[发明名称].md`

**阶段5：转换为 Word 文档**

**【必须】读取 `docx` Skill 了解 python-docx 基础用法**

逐个将 .md 中间产物转换为 .docx（完成一个再转下一个）：

| 源文件 | 目标文件 | 格式要点 |
|--------|---------|---------|
| `权利要求书_[发明名称].md` | `权利要求书_[发明名称].docx` | 格式要点详见 `patent-claims-writing` Skill 的 SKILL.md 阶段3 |
| `说明书_[发明名称].md` | `说明书_[发明名称].docx` | 标题层级：H0文档标题→H1发明名称→H2章节→H3子章节；正文宋体小四，行距1.5倍；表格列宽百分比自适应，跨页表头重复，字号小五（9pt） |
| `说明书摘要_[发明名称].md` | `说明书摘要_[发明名称].docx` | 标题居中，正文宋体小四 |
| `说明书附图_[发明名称].md` | `说明书附图_[发明名称].docx` | Mermaid→PNG→嵌入Word，图片居中 |
| `摘要附图_[发明名称].md` | `摘要附图_[发明名称].docx` | Mermaid→PNG→嵌入Word，图片居中 |

## 核心校验要点

- 前后术语一致，技术描述呼应，因果关系清晰
- 权利要求书技术特征在说明书"技术方案"中有对应描述
- 实施例参数与技术方案"可实现性"匹配
- 有益效果与"技术特征"存在因果关系

## 质量检查

撰写完成后，对照 [references/writing-guide.md](references/writing-guide.md) 的"常见错误及纠正"章节进行检查。

docx 生成阶段需额外检查：
- [ ] 所有最终交付文件均为 .docx 格式（中间产物 .md 不作为交付物）
- [ ] 各 .docx 文件可在 Microsoft Word / WPS 中正常打开，格式无乱码
- [ ] 权利要求书 .docx 中编号加粗、条款间距合理
- [ ] 说明书 .docx 中标题层级清晰、段落缩进正确
- [ ] 附图 .docx 中图片清晰可见、标注完整
