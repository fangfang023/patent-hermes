# 分案布局分析技能

## 定位

本 Skill 解决的核心问题：**一个技术方案中有多个创新点，应该作为一件申请还是多件申请？如何切分？每件申请怎么保护最优？**

覆盖全链路：**创新点识别 → 关联分析 → 创新度评估 → 单一性分组 → 分案策略决策 → 布局输出**。

## 输入

| 输入类型 | 说明 | 必要性 |
|---------|------|--------|
| 技术方案/交底书/创意描述 | 包含多个技术方向的完整技术文档 | 必需 |
| 创新评估报告 | 已有的创新性评估结果 | 可选，有助于更准确的判断 |

## 输出

1. **分案布局分析报告**（Markdown）：包含创新点识别、关联分析、创新度评估、单一性分组、分案策略、保护布局、种子专利回退分析
2. **每组创新点的独立文件**：每组输出一个结构化的创新点描述文件，可直接作为 `tech-disclosure` 的输入

## 执行流程

### 阶段 1：准备

1. 读取 `references/splitting-guide.md` — 创新点识别标准与切分规则
2. 读取 `references/dependency-analysis.md` — 依赖图构建方法
3. 读取 `references/grouping-strategy.md` — 分组策略（核心/外围/防御）
4. 读取 `references/portfolio-layout.md` — 布局建议与驳回风险分析指南
5. 读取 `knowledge/references/divisional-standards.md` — 分案/单一性判断标准
6. 读取 `assets/templates/divisional-report.md` — 报告输出模板

### 阶段 2：创新点识别与提取

分析输入文档，识别所有独立的技术创新点。

**必须执行**：读取 `references/splitting-guide.md` 获取创新点识别标准。

对每个创新点，提取三要素：

| 要素 | 说明 | 示例 |
|------|------|------|
| 技术问题 | 该创新点解决什么技术问题 | "现有技术无法实时处理高并发数据流" |
| 技术手段 | 核心技术方案是什么 | "基于滑动窗口的流式数据处理引擎" |
| 技术效果 | 带来什么有益效果 | "处理延迟降低80%，吞吐量提升3倍" |

**输出**：创新点清单表

### 阶段 3：关联性分析与依赖图

**必须执行**：读取 `references/dependency-analysis.md` 获取分析方法。

对创新点两两之间分析：

| 分析维度 | 判断问题 | 结论 |
|---------|---------|------|
| 技术依赖 | A 是否依赖 B 的输出才能实现？ | 依赖/不依赖 |
| 问题关联 | A 和 B 是否服务于同一技术问题？ | 是/否 |
| 技术同源 | A 和 B 是否共享核心技术特征？ | 是/否 |

构建创新点关联图（有向无环图 DAG），输出邻接矩阵。

### 阶段 4：创新度评估

对每个技术方向独立评估创新度：

| 评估维度 | 评估要点 |
|---------|---------|
| 新颖性 | 该方向的技术特征在现有技术中是否已有 |
| 创造性 | 是否有技术启示使本领域技术人员容易想到 |
| 技术贡献度 | 对整个方案的贡献大小 |
| 独立保护价值 | 单独保护的商业/技术意义 |

输出每个技术方向的创新度等级：

| 等级 | 标准 | 建议 |
|------|------|------|
| **高** | 明显区别于现有技术，技术效果显著 | 独立撰写，核心专利 |
| **中** | 有一定创新，但与现有技术有部分重叠 | 可独立或作为从权，视保护需求 |
| **低** | 基于公知技术的常规优化 | 建议作为从权或放入说明书 |

### 阶段 5：单一性分组

**必须执行**：读取 `references/grouping-strategy.md` 获取分组策略。

基于关联图和创新度评估，执行分组算法：

1. **连通分量识别**：找出 DAG 中所有连通子图
2. **单一性检验**：每组内的创新点是否满足单一性要求（共享相同或相应的特定技术特征）
3. **优先级标注**：
   - 核心专利：解决最关键技术问题、技术手段最基础的组
   - 外围专利：扩展应用场景、上下游技术的组
   - 防御专利：替代实现方案、规避设计的组
4. **组间关联说明**：描述各组之间的关系（依赖、上下游、替代等）

**分组规则**：
- 每组 1-3 个创新点
- 每组聚焦一个技术问题
- 保持组间逻辑关系清晰

### 阶段 6：分案策略决策

基于创新度评估 + 单一性分析，给出分案建议：

#### 决策矩阵

| 条件 | 建议 |
|------|------|
| 所有方向创新度高 + 有单一性 | 合案申请，多组从权 |
| 所有方向创新度高 + 无单一性 | 分案申请 |
| 部分高+部分低 + 有单一性 | 合案，高的放独权，低的放从权 |
| 部分高+部分低 + 无单一性 | 高的方向分案，低的放入说明书 |
| 全部低 | 不建议申请，或完善技术方案 |

#### 从权 vs 独立撰写判断

| 因素 | 倾向从权 | 倾向独立撰写 |
|------|---------|------------|
| 创新度 | 与主案相近，是细化 | 独立创新，与主案平行 |
| 技术关联 | 与主案共享核心技术特征 | 有独立的特定技术特征 |
| 保护需求 | 只需覆盖主案特定实现 | 需要独立保护范围 |
| 审查风险容忍度 | 低（担心主案被驳回牵连） | 高（分案互不影响） |

#### 每组权利要求布局建议

对每组（案件）输出：
- 独权方向（方法侧/系统侧）
- 从权方向（具体实现/参数优化/应用场景）

### 阶段 7：布局建议与输出

**必须执行**：读取 `references/portfolio-layout.md` 获取布局模板和驳回风险分析指南。

#### 7.1 布局建议

- 申请顺序建议（核心优先）
- 分案策略（基于优先权）
- 组间关联的技术说明（确保专利之间的逻辑衔接）

#### 7.2 创新点关联矩阵与种子专利（强制输出章节）

⚠️ **必须输出 7 列属性矩阵表，不得跳过或简化。**

| 创新点 | 当前归属组 | 独立性 | 技术完整性 | 保护价值 | 驳回后存活 | 种子专利建议 |
|--------|----------|--------|----------|---------|----------|------------|
| A | 第1组（核心） | 中 | 完整 | 高 | 高 | ✅ 建议独立申请基础专利 |
| B | 第1组（核心） | 高 | 需补充 | 中 | 中 | ⚠️ 补充实施例后可独立 |
| C | 第2组（外围） | 高 | 完整 | 高 | 高 | ✅ 建议作为独立种子专利 |
| D | 第3组（防御） | 低 | 不完整 | 低 | 低 | ❌ 依赖过强，不建议独立 |

**种子专利策略说明**（必须为每个创新点提供具体理由）：
- ✅ 标注：说明理由（技术方案完整、保护范围广、独立性高），建议同步或优先独立申请
- ⚠️ 标注：列出需要补充的具体技术内容，补充后可独立申请
- ❌ 标注：说明依赖原因（具体指出依赖哪个创新点、为什么无法脱离）

#### 7.3 种子专利回退分析（强制输出章节）

⚠️ **必须输出以下三个子章节，不得跳过。**

1. **回退矩阵**：对每组专利，分析不同驳回场景下可拆出的种子创新点

| 原始组 | 驳回/部分驳回场景 | 可拆出的种子创新点 | 独立申请可行性 | 建议申请形式 |
|--------|----------------|------------------|--------------|-------------|
| 第N组 | [具体驳回场景] | [创新点编号+名称] | [高/中/低，附理由] | [方法+系统/...] |

2. **种子专利独立条件分析**

| 种子创新点 | 独立解决的技术问题 | 不依赖其他创新点的理由 | 需要补充的技术描述 |
|-----------|-----------------|---------------------|------------------|

3. **回退策略建议**

| 场景 | 策略 | 具体操作 |
|------|------|---------|
| 整组被驳回 | | |
| 部分权利要求被驳回 | | |
| 审查员认为不满足单一性 | | |

#### 7.4 输出文件

**必须执行**：读取 `assets/templates/divisional-report.md` 获取报告模板。

⚠️ **输出报告时，必须严格对照模板的每个章节逐项输出，不得跳过任何章节。**

输出文件：

1. **分案布局分析报告**：`./generated_docs/分案布局分析_[技术方向]_[timestamp].md`
2. **每组创新点描述**：`./generated_docs/分案布局_[技术方向]_第N组_[timestamp].md`（N = 1, 2, 3...）

每组创新点描述文件必须包含：

## 质量检查

| 检查项 | 标准 |
|--------|------|
| 创新点识别完整性 | 所有关键创新点都被识别，三要素齐全 |
| 关联性分析合理性 | DAG 构建有依据，邻接矩阵无遗漏 |
| 创新度评估合理性 | 评估有依据，不是主观臆断 |
| 单一性判断准确性 | 引用了具体的法条和判断标准 |
| 每组创新点数 | 每组 1-3 个创新点，超过则重新拆分 |
| 分案建议可操作性 | 每个建议都有明确的理由 |
| 保护策略实用性 | 考虑了成本、风险、商业价值 |
| 种子专利分析完整性 | 7 列矩阵表 + 回退三子章节齐全 |
