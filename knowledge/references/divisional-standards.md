# 分案与单一性判断标准

## 1. 法律依据

### 《专利法》第三十一条（单一性）

一件发明或者实用新型专利申请应当限于一项发明或者实用新型。属于一个总的发明构思的两项以上的发明或者实用新型，可以作为一件申请提出。

### 《专利法实施细则》第四十二条

一件专利申请包括两项以上发明、实用新型或者外观设计的，申请人可以在专利局发出授予专利权的通知前，向专利局提出分案申请。

### 《专利审查指南》第二部分第六章

单一性是指一件申请的内容应当限于一项发明创造。判断标准是：两项以上的发明或者实用新型是否属于一个总的发明构思，即在技术上是否相互关联。

---

## 2. 单一性判断方法

### 2.1 核心判断标准

**单一性判断 = 是否包含相同或相应的特定技术特征**

- **特定技术特征**：每一项发明作为整体，对现有技术做出贡献的技术特征
- 两项以上发明之间含有**相同或相应的特定技术特征** → 具有单一性
- 两项以上发明之间**不含相同或相应的特定技术特征** → 不具有单一性

### 2.2 判断步骤

```
步骤1：确定每项发明的特定技术特征
  → 该发明区别于现有技术的技术特征

步骤2：比较各项发明之间的特定技术特征
  → 是否存在相同或相应的特定技术特征

步骤3：判断
  → 存在相同/相应特定技术特征 → 具有单一性，可作为一件申请
  → 不存在 → 不具有单一性，需要分案
```

### 2.3 常见情形

| 情形 | 单一性判断 | 处理建议 |
|------|----------|---------|
| 共同的方法+基于该方法的设备 | 通常有单一性 | 同一申请 |
| 共同的核心算法+不同应用场景 | 通常有单一性 | 同一申请，不同从权 |
| 两个独立的技术方案解决不同技术问题 | 通常无单一性 | 分案 |
| 方法权利要求+存储介质权利要求 | 通常有单一性 | 同一申请 |
| 独立产品权利要求+独立方法权利要求（解决同一技术问题） | 需要具体分析 | 看是否共享特定技术特征 |
| 上位概念的权利要求+多个下位概念的实施例 | 通常有单一性 | 同一申请，从权保护 |

## 3. 分案策略

### 3.1 何时考虑分案

- 技术方案中存在**两个以上独立的技术贡献**，解决不同技术问题
- 创新点之间**关联度低**，不属于同一技术构思
- 一个创新点聚焦**算法/方法**，另一个聚焦**系统/架构**
- 专利代理师希望在**不同技术方向**上分别获得保护

### 3.2 母案与分案的关系

```
母案（主案）
├── 包含最核心的、总的技术构思
├── 独立权利要求覆盖最宽泛的保护范围
└── 说明书记载所有实施例（包括分案的内容）

分案1
├── 从母案中分离出的一个特定技术方向
├── 独立权利要求与母案不重叠
└── 可以引用母案的优先权

分案2
├── 另一个特定技术方向
└── 与分案1也无单一性（但各自与母案有单一性）
```

### 3.3 从权 vs 独立撰写的决策

| 因素 | 作为从权 | 独立撰写（分案） |
|------|---------|---------------|
| 创新程度 | 与母案创新度相近，是母案的细化 | 创新度独立，与母案是平行关系 |
| 保护需求 | 只需要覆盖母案的特定实现 | 需要独立保护范围 |
| 技术关联 | 与母案共享核心技术特征 | 有独立的特定技术特征 |
| 成本 | 低（一件申请） | 高（多件申请） |
| 审查风险 | 母案被驳回则从权全部失效 | 分案独立审查，互不影响 |

### 3.4 权利要求的上位策略

当母案与分案需要区分时，常用以下方法：

1. **术语上位**：母案用上位概念（如"约束求解器"），分案用下位概念（如"静态约束求解器"+"动态约束求解器"）
2. **流程切分**：母案覆盖完整流程，分案只覆盖其中的关键子流程
3. **执行主体区分**：母案从系统侧撰写，分案从方法侧/设备侧撰写
4. **应用场景区分**：母案覆盖通用场景，分案覆盖特定应用场景

## 4. 分案时间节点

| 阶段 | 能否分案 | 说明 |
|------|---------|------|
| 申请日前 | 可以合案申请 | 最灵活 |
| 审查中 | 可以主动分案 | 收到授权通知书前 |
| 收到授权通知书后 | 2个月内可以分案 | 期限紧张 |
| 授权后 | 不能分案 | 除非通过放弃专利权重新申请 |

## 5. 典型案例分析

### 案例1：AI编程系统

技术方案包含：
- A. 意图编译器（自然语言→结构化指令）
- B. 静态约束求解器 + UI降级渲染器
- C. 确定性执行器 + Saga事务机制

**分析**：
- A+B+C 作为一个整体具有单一性（共享"AI辅助编程"的总构思）
- 但 B 和 C 各自也有独立的特定技术特征
- **建议**：母案覆盖 A+B+C 的完整链路，分案1聚焦 B（约束求解+降级），分案2聚焦 C（确定性执行+事务机制）

### 案例2：多级熔断决策系统

技术方案包含：
- A. 多维度特征感知评估
- B. 三级递进式决策算法
- C. 协同推理 + 噪声适配

**分析**：
- A+B 是调度决策链路，C 是模型推理优化，技术方向不同
- 但 A 的评估结果直接影响 C 的触发条件
- **建议**：母案覆盖 A+B+C 的整体方案，分案聚焦 C 的噪声适配训练方法
