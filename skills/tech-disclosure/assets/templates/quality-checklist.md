# 技术交底书质量检查清单

生成技术交底书后，请使用本清单进行质量检查。

---

## 一、内容完整性

- [ ] 所有6个必需章节都存在
  - 发明名称
  - 技术领域
  - 背景技术
  - 发明内容（发明目的、技术方案、有益效果）
  - 附图说明
  - 具体实施方式

- [ ] 背景技术清楚指出了问题（聚焦1-2个核心技术问题）
- [ ] 技术方案充分公开，包含实现机制
- [ ] 技术方案中每个核心创新点包含"与现有技术对比"
- [ ] 有益效果有据可依，包含：
  - 解决现有技术的缺陷（具体指出解决了哪个现有技术的哪个缺陷）
  - 技术依据（因采用什么具体技术特征）
  - 对比效果（量化数据或定性说明）
  - 实现原理（技术解释）
- [ ] 实施方式细节足以重现

---

## 二、术语一致性

- [ ] 全文使用相同的技术术语
- [ ] 前后描述没有矛盾

---

## 三、专利符合性

- [ ] 发明名称在25字以内

---

## 四、技术深度检查

### 4.1 与现有技术对比完整性

- [ ] 每个核心创新点都包含"与现有技术对比"部分
- [ ] 对比包含以下4个维度：
  - 技术手段（现有技术 vs 本发明）
  - 实现方式（现有技术 vs 本发明）
  - 技术效果（现有技术 vs 本发明）
  - 关键参数（现有技术 vs 本发明）
- [ ] 每个维度都说明了改动原因

### 4.2 有益效果完整性

- [ ] 每个有益效果包含以下4要素：
  - 解决现有技术的缺陷（具体指出解决了背景技术中哪个现有技术的哪个缺陷）
  - 技术依据（因采用什么具体技术特征）
  - 对比效果（量化对比数据或定性说明）
  - 实现原理（技术解释）
- [ ] 有益效果与技术方案中的创新点形成对应关系
- [ ] 有益效果与背景技术中的缺陷形成呼应

### 4.3 技术模块深度

- [ ] 每个技术模块都说明了：
  - 功能定位
  - 实现机制
  - 具体实现

- [ ] 每个技术选择都有依据
- [ ] 技术实现流程有完整的逻辑链条
- [ ] 避免了空洞的功能性描述

---

## 五、技术实现充分性检查

### 5.1 数据流完整性

- [ ] 明确说明每个模块的输入数据类型和格式
- [ ] 明确说明每个模块的输出数据类型和格式
- [ ] 明确说明模块间数据传输方式（API/消息队列/共享内存等）
- [ ] 明确说明异常情况处理（数据丢失、格式错误、超时等）

### 5.2 技术参数完整性

- [ ] 核心算法参数（如学习率、迭代次数、阈值等）
- [ ] 系统配置参数（如并发数、缓存大小、超时时间等）
- [ ] 数据规模参数（如训练数据量、向量维度等）

### 5.3 接口定义完整性

- [ ] 内部模块间接口（函数签名、数据结构）
- [ ] 外部服务接口（API端点、请求/响应格式）

### 5.4 实施案例充分性

- [ ] 包含完整的端到端实施流程
- [ ] 每个步骤有具体的输入输出
- [ ] 每个步骤有具体的技术手段
- [ ] 包含实际可运行的参数配置

---

## 六、逻辑连贯性检查

- [ ] 没有出现"智能处理"、"自动分析"等空洞描述
- [ ] 没有堆砌技术术语而不说明其作用
- [ ] 因果关系清晰（采用某技术→实现某效果）
- [ ] 前后描述呼应，没有矛盾

---

## 七、词语堆积检测

- [ ] 没有使用"智能"、"先进"、"高效"等形容词而不说明具体含义
- [ ] 没有堆砌技术术语（如"大数据、人工智能、云计算"）而不说明作用
- [ ] 没有重复相同内容以凑字数

---

## 八、创新点关联性检查

- [ ] 创新点之间存在技术依赖关系
- [ ] 创新点服务于同一技术问题
- [ ] 创新点组合产生协同效应（1+1>2）
- [ ] 属于同一发明构思

---

## 九、数学公式格式检查

> **详细规范请参考**：`../SKILL.md` 中的"原则六：数学公式LaTeX格式规范原则"

- [ ] 所有数学公式使用LaTeX格式（`$...$` 内联 或 `$$...$$` 块级）
- [ ] 上标下标：使用 `$x^2$`, `$W_{MT}$` 格式
- [ ] 希腊字母：使用 `$\alpha, \beta, \sigma$` 格式
- [ ] 集合/分数/求和/积分等复杂元素：使用对应LaTeX命令
- [ ] 未使用Unicode文本符号表示数学元素（如 `∈`, `^(256)`, `W_MT`）
- [ ] 公式格式支持 `pandoc --mathml` 转换
