# 权利要求溯源映射表

基于已生成的专利文件（权利要求书、说明书）和原始输入（交底书/技术方案），自动生成溯源映射表。

## 核心价值

1. **校对辅助**：快速定位每个权利要求特征的出处，检查是否有遗漏或偏离
2. **审查应对**：审查员质疑"权利要求X的特征是否在原始交底书中有依据"时，一键定位
3. **一致性校验**：发现权利要求书→说明书→交底书之间的描述断层

## 输入

必须提供以下文件路径（至少提供权利要求书和一项原始输入）：

| 输入文件 | 必要性 | 说明 |
|---------|--------|------|
| 权利要求书 | **必须** | 已生成的权利要求书 .md 文件路径 |
| 说明书 | **必须** | 已生成的说明书 .md 文件路径 |
| 交底书/技术方案 | **必须** | 原始输入文档 .md 文件路径 |

## 输出

- **溯源映射表**：`./generated_docs/溯源映射表_[发明名称]_[timestamp].md`

## 执行流程

### 阶段 1：读取参考规范

读取 `references/mapping-guide.md` 了解映射表字段定义和输出格式。

### 阶段 2：文档加载与解析

逐个读取三份文档，提取结构化信息：

1. **权利要求书**：提取每条权利要求的编号、引用关系、技术特征列表
2. **说明书**：提取章节结构（技术领域、背景技术、发明内容、具体实施方式）、各章节覆盖的技术特征
3. **交底书/技术方案**：提取章节结构和段落划分，标注段落编号

### 阶段 3：特征匹配与映射

对权利要求书中的每条权利要求的每个关键技术特征：

1. 在交底书中定位最匹配的段落（精确到"第N章第M段"或"§N.M"）
2. 在说明书中定位对应的描述章节（精确到"发明内容/具体实施方式"的子章节）
3. 在实施例中定位是否有具体体现（标注哪个实施例）
4. 标注匹配置信度：**精确匹配** / **语义等价** / **推断对应** / **未找到依据**

### 阶段 4：一致性校验

基于映射结果，检查以下问题：

| 检查项 | 判定标准 |
|--------|---------|
| 溯源缺失 | 权利要求特征在交底书中"未找到依据" |
| 说明书断链 | 权利要求特征在说明书中无对应描述 |
| 实施例空白 | 独立权利要求的必要特征没有实施例支撑 |
| 术语漂移 | 同一技术特征在三份文档中用词不一致 |

### 阶段 5：输出生成

按照 `references/mapping-guide.md` 中的模板格式输出溯源映射表。

## 质量要求

1. **覆盖率**：权利要求中所有技术特征必须出现在映射表中，不得遗漏
2. **精确度**：段落定位应精确到最小可定位单元（段落/条目），不要笼统标注"背景技术部分"
3. **诚实标注**：找不到对应关系时如实标注"未找到依据"，不要强行匹配
4. **一致性检查结果**：如有问题必须在"一致性校验"章节中明确列出
