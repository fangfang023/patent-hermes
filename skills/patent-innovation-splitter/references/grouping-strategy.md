# 分组策略：核心/外围/防御

## 一、分组原则

### 核心规则

1. **强依赖必合并**：如果创新点 A 和 B 之间存在强依赖关系，必须在同一组
2. **独立必拆分**：如果创新点之间完全无关联，必须拆分到不同组
3. **每组聚焦一题**：每组创新点应围绕一个核心技术问题
4. **每组 1-3 点**：确保权利要求结构清晰，独立权利要求不过多

### 分组决策流程

```
Step 1: 强依赖的创新点 → 合并为同一组
    ↓
Step 2: 协同关系的创新点 → 倾向合并为同一组
    ↓
Step 3: 弱依赖的创新点 → 根据单一性判断
    ↓
Step 4: 独立的创新点 → 拆分到不同组
    ↓
Step 5: 检验每组的单一性
    ↓
Step 6: 标注每组的优先级类型
```

## 二、优先级分类

### 核心专利组

**特征**：
- 解决最基础、最关键的技术问题
- 技术手段具有基础性和通用性
- 其他组的创新点可能依赖此组
- 独立权利要求的保护范围最广

**判断标准**：
- [ ] 该组创新点是否是整个技术方案的基础？
- [ ] 其他组是否依赖该组的技术特征？
- [ ] 去掉该组，整个技术方案是否失去核心价值？

**符合任意一条 → 核心专利组**

### 外围专利组

**特征**：
- 扩展核心专利的应用场景
- 覆盖上下游技术环节
- 针对特定领域或特定场景的优化

**判断标准**：
- [ ] 该组是否扩展了核心组的应用范围？
- [ ] 该组是否覆盖了核心组的上游（数据采集、输入）或下游（输出、展示）？
- [ ] 该组是否针对特定场景做了优化？

**符合任意一条 → 外围专利组**

### 防御专利组

**特征**：
- 提供核心技术的替代实现方案
- 覆盖竞争对手可能绕过的路径
- 防止规避设计

**判断标准**：
- [ ] 该组是否提供了核心组的替代方案？
- [ ] 该组是否覆盖了核心组中可替换的组件？
- [ ] 竞争对手是否容易通过该组描述的方式绕过核心专利？

**符合任意一条 → 防御专利组**

## 三、分组数量控制

| 创新点总数 | 建议分组数 | 说明 |
|-----------|----------|------|
| 3-4 个 | 2 组 | 核心1 + 外围/防御1 |
| 5-6 个 | 2-3 组 | 核心1 + 外围1 + 防御0-1 |
| 7-9 个 | 3-4 组 | 核心1 + 外围1-2 + 防御1 |
| 10+ 个 | 4-5 组 | 核心1 + 外围2-3 + 防御1 |

**注意**：分组过多会导致专利维护成本高。如果超过 5 组，需要重新审视是否有创新点粒度过细的问题。

## 四、分组示例

### 示例：智能客服系统（6个创新点）

**创新点清单**：
- A: 基于意图识别的多轮对话管理方法
- B: 上下文感知的语义理解模型
- C: 动态知识库检索与融合方法
- D: 多模态输入（语音+文本+图像）预处理
- E: 情感分析驱动的应答策略调整
- F: 基于强化学习的对话策略优化

**依赖分析**：
- A 强依赖 B（意图识别需要语义理解）
- A 弱依赖 C（对话管理可使用知识库信息）
- E 协同 B（情感分析也使用语义理解结果）
- F 协同 A（强化学习优化对话策略）
- D 独立（输入预处理与其他环节无强关联）

**分组结果**：

| 组 | 包含 | 类型 | 理由 |
|----|------|------|------|
| 第1组（核心） | A, B | 核心专利 | A强依赖B，构成对话管理的核心引擎 |
| 第2组（外围） | C, E | 外围专利 | C和E协同增强核心对话能力，共享语义理解基础 |
| 第3组（防御） | D | 防御专利 | 输入预处理是独立模块，替代方案保护 |
| 第4组（外围） | F | 外围专利 | 基于核心专利的优化策略，可独立申请 |

## 五、特殊情况处理

### 情况1：所有创新点强关联

如果所有创新点形成一条强依赖链（A→B→C→D），**不拆分**，保持为一个专利。

判断：这种情况下创新点属于一个总的发明构思，满足单一性。

### 情况2：创新点之间存在矛盾

如果两个创新点互斥（是同一问题的两种对立解决方案），处理方式：
- 放入同一组，通过从属权利要求分别保护
- 或拆分为两组，一组为正面方案，一组为防御方案

### 情况3：无法明确分组

如果创新点之间的关联性模糊，优先**保守分组**（合并不拆分），避免破坏单一性。
