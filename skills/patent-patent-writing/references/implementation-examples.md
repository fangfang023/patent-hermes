## 实施例构造方法论

### 核心原则

实施例不是交底书方案的复述，而是**从权利要求书的技术特征出发，构造多个不同场景下的具体实现方式**。每个实施例是一个独立的、可运行的技术实例。

### 构造步骤

**第一步：提取权利要求书中的技术特征**

从独立权利要求和从属权利要求中提取全部技术特征，列出特征清单：
- 必要技术特征（独立权利要求中的特征）
- 附加技术特征（从属权利要求中的特征）

**第二步：确定实施例的场景差异维度**

选择2-3个不同的差异维度来构造实施例，常见维度包括：

| 差异维度 | 示例 |
|---------|------|
| **应用行业** | K12教育 vs 企业培训 vs 高等教育 |
| **用户群体** | 个人用户 vs 企业用户 vs 政府机构 |
| **技术环境** | 移动端 vs PC端 vs IoT嵌入式 |
| **数据规模** | 小规模单机部署 vs 中规模集群 vs 大规模分布式 |
| **算法选择** | 方案A（精度优先） vs 方案B（速度优先） |
| **硬件配置** | 低成本方案 vs 标准方案 vs 高性能方案 |

**第三步：为每个实施例填充具体参数**

根据选择的差异维度，为每个实施例设定：
- 具体的硬件型号和配置参数
- 具体的软件框架版本和算法参数
- 适配该场景的操作步骤
- 预期能达到的效果

### 构造示例

假设权利要求的技术方案为"基于多模态数据的学习动机评估方法"：

| | 实施例1：K12在线教育 | 实施例2：企业技能培训 | 实施例3：高等教育 |
|---|---|---|---|
| **硬件** | 学生平板+心率手环 | PC+摄像头+麦克风 | 智慧教室终端+眼动仪 |
| **采集数据** | 学习行为+心率+表情 | 操作日志+语音+姿态 | 笔记行为+眼动+表情 |
| **算法参数** | LSTM，隐藏层128，学习率0.001 | Transformer，8头注意力 | GCN+LSTM混合 |
| **操作流程** | 学生自主学习场景下的评估流程 | 员工在岗培训场景下的评估流程 | 翻转课堂场景下的评估流程 |

> **注意**：各实施例的技术参数和操作流程必须有实质差异，不能只改名称而内容雷同。

## 实施例结构

每个实施例应包含以下四个部分：

1. **硬件配置** - 具体的硬件设备和参数
2. **软件参数** - 软件环境、算法、框架配置
3. **操作步骤** - 详细的操作流程
4. **预期效果** - 预期实现的定性效果

## 实施例撰写要点

### 1. 硬件配置
- 具体到品牌、型号、规格
- 说明各设备的功能和作用
- 合理配置，不追求过高配置

### 2. 软件参数
- 明确开发环境（语言、框架版本）
- 说明算法名称和关键参数
- 明确部署方式

### 3. 操作步骤
- 步骤之间逻辑连贯
- 每步说明输入、处理、输出
- 参数设置具体明确

### 4. 预期效果
- 使用定性描述，避免虚构具体数据
- 说明技术手段与效果的因果关系
- 与实施例中的技术方案对应

### 5. 避免事项

| 禁止行为 | 原因 |
|---------|------|
| 虚构未经验证的具体实验数据 | 可能误导审查员，降低可信度 |
| 夸大效果，使用"完美"、"100%"等绝对化表述 | 可能被认定为宣传性用语 |
| 描述与实施例技术方案不相关的效果 | 超出技术方案范围，可能导致支持不足 |

**推荐表述：**
- 使用"预计可实现"、"预期为"等预期性表述
- 说明技术手段如何实现效果的机制
