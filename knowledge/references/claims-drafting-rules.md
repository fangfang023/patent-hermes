# 权利要求撰写常见问题清单

本文件用于权利要求审查和修改时逐条检查。分为形式问题和逻辑问题两大类。

---

## 1. 形式问题检查清单

### 1.1 独立权利要求结构

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 前序部分 | 必须包含主题名称（产品/方法） | 主题名称缺失或不明确 |
| 前序部分 | 写明共有必要技术特征 | 前序过于笼统，如"一种系统" |
| 特征部分 | 必须使用"其特征在于"引导 | 缺少"其特征在于"或用其他表述替代 |
| 特征部分 | 写明区别必要技术特征 | 特征部分包含非必要特征 |
| 主题匹配 | 主题名称与发明客体匹配 | 方法权利要求的主题写成"一种系统" |

### 1.2 从属权利要求结构

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 引用关系 | 必须明确引用在前的一项或多项权利要求 | 未写引用关系 |
| 引用逻辑 | 只能引用在前的权利要求 | 引用在后的权利要求（向前引用） |
| 引用层次 | 引用的权利要求本身必须完整有效 | 引用了一个缺少必要特征的权利要求 |
| 附加特征 | 只能包含附加技术特征 | 包含了应该放在独权中的必要技术特征 |
| 多项引用 | 引用两项以上时只能采取择一引用 | 同时引用多个权利要求且未明确择一 |

### 1.3 用语规范

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 技术术语 | 使用规范技术术语 | 使用非标准或自造术语未定义 |
| 表述方式 | 优先使用肯定式表述 | 大量使用"不包括""非"等否定式 |
| 宣传用语 | 禁止使用宣传性词汇 | 出现"高效""智能""创新""最优"等 |
| 模糊用语 | 禁止模糊表述 | 出现"大约""可能""优选""较佳""最好是" |
| 功能限定 | 慎用，确需使用时说明书必须充分公开实现手段 | 功能性限定的特征在说明书中找不到对应实现 |
| 数值范围 | 必须有说明书支持 | 权要中的数值范围超出说明书记载 |

### 1.4 格式规范

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 编号顺序 | 从1开始连续编号 | 编号跳跃或重复 |
| 分句标点 | 每个技术特征之间用分号分隔 | 用逗号分隔导致特征边界不清 |
| 结尾标点 | 独权和最后一个从权用句号结尾 | 中间的从权用了句号 |
| 附图标记 | 放在技术特征后面的括号内 | 附图标记放在特征前面或缺少括号 |

## 2. 逻辑问题检查清单

### 2.1 必要技术特征完整性

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 技术问题对应 | 独权必须包含解决技术问题的全部必要特征 | 遗漏了关键步骤或组件 |
| 方案完整性 | 独权描述的方案必须能独立实现 | 缺少关键输入/输出/中间处理步骤 |
| 非必要特征 | 不应包含非必要特征 | 把优选实施方式写进了独权，缩小了保护范围 |

### 2.2 数据流/流程逻辑

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 输入来源 | 每个处理步骤的输入必须明确来源 | 输入数据凭空出现 |
| 输出去向 | 每个处理步骤的输出必须明确去向 | 中间结果没有后续处理或使用 |
| 执行顺序 | 步骤之间顺序逻辑合理 | 依赖前置结果的步骤放在了前面 |
| 条件判断 | 条件分支必须覆盖所有必要情况 | 只处理了"是"的情况，未处理"否"的情况 |
| 数据一致性 | 前后步骤使用的数据类型/格式一致 | 前一步输出类型A，后一步直接按类型B处理 |

### 2.3 权利要求之间的逻辑关系

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 独权之间 | 多个独权应属于同一发明构思 | 两个独权解决完全不同的技术问题 |
| 从权展开 | 从权应该是对被引用权要的细化 | 从权引入了与被引用权要无关的新内容 |
| 保护范围层次 | 权利要求范围从独权到从权逐步缩小 | 从权的保护范围反而比独权更宽 |
| 引用链完整性 | 引用链不断裂 | 从权引用了一个不存在的权利要求编号 |

### 2.4 技术方案的逻辑自洽

| 检查项 | 规则 | 常见错误 |
|--------|------|---------|
| 因果关系 | 技术特征与技术效果之间有明确因果关系 | 声称的技术效果缺乏技术特征支撑 |
| 实施可行性 | 权要描述的方案技术上可实施 | 描述了不可能实现的技术组合 |
| 一致性 | 权要中的术语含义前后一致 | 同一术语在不同位置含义不同 |
| 说明书支持 | 权要的范围不超出说明书公开的内容 | 权要涵盖了说明书中未记载的实施方式 |

## 3. 修改权利要求时的检查要点

### 3.1 上位化修改

- 上位概念必须在说明书中有依据（已有多个下位实施例支撑）
- 上位后不能引入说明书中未记载的新内容
- 上位后保护范围不能超出原申请文件记载的范围
- 上位概念必须在本领域有明确、公认的含义

### 3.2 补充从属权利要求

- 补充的从权内容必须来源于说明书记载的实施例
- 不能通过补充从权的方式添加新的技术方案
- 补充后引用关系必须正确

### 3.3 响应审查意见的修改

- 修改不能超出原说明书和权利要求书记载的范围（《专利法》第三十三条）
- 可以：删除权利要求、缩小保护范围、澄清模糊表述
- 不可以：扩大保护范围、添加新内容、改变发明主题
- 修改后的权利要求必须具有新颖性和创造性

## 4. 独立权利要求撰写质量自检表

对每个独立权利要求，逐项检查：

```
[ ] 主题名称是否明确（产品/方法/系统/设备/存储介质）
[ ] 前序部分是否包含共有必要技术特征
[ ] "其特征在于"是否正确使用
[ ] 特征部分是否包含全部必要技术特征
[ ] 是否避免了非必要特征
[ ] 用语是否规范（无宣传词、无模糊词）
[ ] 技术方案是否完整可实施
[ ] 是否与说明书一致
[ ] 是否符合单一性要求
[ ] 保护范围是否合理（不过宽也不过窄）
```

## 5. 从属权利要求撰写质量自检表

对每个从属权利要求，逐项检查：

```
[ ] 引用关系是否明确（引用哪一项）
[ ] 引用是否正确（只能引用在前的权利要求）
[ ] 附加技术特征是否是对被引用权要的细化
[ ] 是否引入了与被引用权要无关的新内容
[ ] 保护范围是否比被引用权要更窄
[ ] 用语是否规范
[ ] 是否得到说明书支持
```
