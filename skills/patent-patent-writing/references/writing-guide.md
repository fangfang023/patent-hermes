## CNIPA 审查指南核心要点

### 发明专利申请文件的基本要求

1. **充分公开**：说明书应当对发明作出清楚、完整的说明，使所属技术领域的技术人员能够实现
2. **清楚完整**：权利要求书应当以说明书为依据，清楚、简要地限定要求专利保护的范围
3. **支持关系**：权利要求书的技术特征必须在说明书中有充分支持

### 技术方案的撰写要求

必须包含的技术要素：
1. **技术领域**：明确指出发明所属或应用的技术领域
2. **背景技术**：写明对发明理解、检索、审查有用的背景技术
3. **发明内容**：解决的技术问题、技术方案、有益效果
4. **具体实施方式**：详细描述实现发明的优选方式
5. **附图说明**：说明附图的图面和内容

### 禁止事项

| 禁止项 | 说明 |
|-------|-----|
| 功能性限定 | 需限定具体技术手段 |
| 模糊表述 | 关键参数避免"优选范围"、"大约"等 |
| 商业宣传 | 不包含"最先进"、"首创"等宣传性用语 |
| 非技术内容 | 不得涉及政治、宗教、社会问题等 |

## 说明书与交底书的本质区别

这是撰写说明书时必须牢记的核心原则。说明书不是交底书的改写或格式调整，而是一份独立的、具有法律效力的技术文献。

### 文档性质差异

| 维度 | 交底书 | 说明书 |
|------|--------|--------|
| **性质** | 企业内部技术沟通文档 | 专利申请的法律文件 |
| **读者** | 专利代理师、内部技术人员 | 审查员、公众、法官 |
| **目的** | 让代理师理解发明内容 | 使所属技术领域技术人员能够实现该发明 |
| **语言** | 可用通俗/口语化表述 | 必须使用正式、规范的专利语言 |
| **深度** | 描述"做了什么" | 必须详述"怎么做、为什么这么做、效果如何" |

### 各章节的具体差异

#### 背景技术
- **交底书**：简要说明现有技术的不足，通常只列举痛点
- **说明书**：需要对3-5种相关现有技术进行独立分析，每种技术必须描述核心原理、技术流程、主要特点、技术局限，并提炼共性技术痛点。不能照抄交底书的现有技术描述

#### 发明内容
- **交底书**：从发明人角度描述技术方案的整体思路
- **说明书**：必须以权利要求书为骨架展开，包含要解决的技术问题、完整技术方案（整体架构+核心模块+关键技术特征+工作原理）、有益效果（因果对应+可验证）

#### 具体实施方式
- **交底书**：通常只描述一个技术方案的实现方式
- **说明书**：必须基于权利要求书中的技术特征，展开至少2-3个不同应用场景的具体实施例。每个实施例从不同角度（不同行业场景、不同硬件配置、不同参数范围）展示技术方案的可实施性

### 禁止行为

| 禁止 | 原因 |
|------|------|
| 直接复制交底书段落作为说明书内容 | 交底书语言不符合专利文件规范，且深度不足 |
| 仅复述交底书中的那一个方案作为实施例 | 说明书需要展示技术方案在多种场景下的可实施性 |
| 用交底书的口语化表述替代专利正式语言 | 说明书是法律文件，语言风格有严格要求 |

## 1. 技术领域

### 撰写要点
- 细化至具体技术领域，避免过于宽泛
- 可以指出发明的一个或多个具体应用领域

### 示例对比

| 错误示例 | 正确示例 |
|---------|---------|
| 本发明涉及计算机技术领域 | 本发明属于计算机视觉技术领域，具体涉及基于深度学习的人脸识别方法 |
| 本发明涉及通信技术 | 本发明属于无线通信技术领域，具体涉及5G网络中的资源调度方法 |

## 2. 背景技术

### 撰写结构

针对3-5种相关现有技术，分别描述：
- 核心原理：该技术的基本工作原理
- 技术流程：技术实现的完整流程
- 主要特点：该技术的主要优点
- 技术局限：该技术的不足之处及原因

### 技术痛点总结
提炼现有技术未解决的共性问题，每个痛点必须是具体的技术问题。

### 示例模板

```
现有技术1：基于问卷调查的学习动机评估方法
- 核心原理：通过发放学习动机量表，收集学生的主观反馈数据，通过统计分析得出动机水平
- 技术流程：设计量表→发放问卷→收集数据→统计分析→输出评估结果
- 主要特点：实施简单、成本较低、易于大规模应用
- 技术局限：依赖学生主观自评，存在社会期许效应，真实性不足；仅在学期末进行评估，无法捕捉动态变化

现有技术2：基于学习行为数据的评估方法
- 核心原理：通过记录学生的在线学习行为（如登录次数、观看时长、作业完成情况），分析其学习投入度
- 技术流程：采集行为数据→提取特征→构建预测模型→输出评估结果
- 主要特点：数据客观、可实时评估
- 技术局限：仅反映外显行为，未考虑认知状态、情绪状态等内在因素；无法区分"表面投入"与"深度学习"

技术痛点总结：
1. 主观自评数据真实性不足，存在显著偏差
2. 仅考虑外显行为，评估维度不完整
3. 评估周期长，无法实时捕捉学习状态变化
```

## 3. 发明内容

### 3.1 要解决的技术问题

**撰写要求**：
- 针对背景技术的缺陷，列出3-5个具体技术问题
- 明确问题的技术边界
- 避免非技术问题（如"解决教育资源分配不均"属于社会问题）

### 3.2 技术方案

#### 整体架构模板

**硬件架构模板**：
```
硬件架构：
- 终端设备层：包括[具体设备及其功能]
  * 设备A：[功能描述，实现方式]
  * 设备B：[功能描述，实现方式]
- 数据传输层：通过[具体网络技术]实现[功能]
- 云端处理层：包括[具体服务器配置及其功能]
```

**软件架构模板**：
```
软件架构：
- 前端模块：[功能描述，实现技术]
- 后端服务：[功能描述，实现技术]
- 数据存储：[功能描述，存储方案]
```

#### 核心组成模块模板

每个模块必须包含：

```
模块名称：[模块名称]

功能定位：
- 该模块在整体技术方案中的作用
- 该模块要解决的具体技术问题
- 该模块的输入和输出

实现机制：
- 采用什么技术实现？（算法/硬件/协议）
- 技术原理是什么？
- 关键技术参数是什么？
- 为什么选择这个技术？

具体实现：
- 硬件实现：[如"采用型号为XYZ的心率传感器，采样频率1Hz"]
- 软件实现：[如"基于Python3.8开发，使用PyTorch框架"]
- 算法流程：[详细描述算法步骤]
```

#### 关键技术特征

分为两类：
- **主要解决技术问题的特征**（3-5个）
- **进一步优化解决技术问题的特征**（2-3个）

每个特征必须说明：特征是什么、为什么采用这个特征、这个特征如何解决技术问题、实现这个特征的技术细节是什么。

#### 工作原理模板

构建完整的技术实现逻辑链条：

```
步骤1：[步骤名称]
- 输入：[具体数据/条件]
- 处理：[采用什么技术，如何处理]
- 输出：[处理结果]
- 与下一步的关系：[为什么需要这个步骤]
```

### 3.3 有益效果

**撰写要求**：
- 与现有技术逐一对比
- 量化技术优势
- 明确"因采用XX技术特征，故实现XX效果"的因果关系
- 说明技术效果的可验证性

**模板**：
```
与现有技术相比，本发明具有以下有益效果：

效果1：[效果标题]
原因：因采用[技术特征]，故实现[效果]
对比：[量化对比数据]
技术依据：[技术原理说明]

可验证性：[说明如何验证技术效果]
```

## 4. 具体实施方式

### 撰写要求
- 提供2-3个完整实施例
- 每个实施例需包含：
  - 硬件配置（具体型号、参数）
  - 软件参数（算法、框架、配置）
  - 操作步骤（详细的操作流程）
  - 预期效果（定性描述，禁止虚构具体数据）

详细模板和示例见 [references/implementation-examples.md](references/implementation-examples.md)。

## 5. 说明书附图说明

### 撰写要求
- 明确附图数量（≥2幅）
- 每幅附图的名称及核心内容

**模板**：
```
本说明书附图共[N]幅：

图1：系统整体架构图
说明：展示终端设备层、数据传输层、云端处理层的模块组成及连接关系

图2：多模态数据融合算法流程图
说明：包含数据预处理、特征提取、权重分配、融合输出4个步骤

图3：评估模型训练流程图
说明：包括数据标注、模型构建、参数优化、效果验证环节
```

## 常见错误及纠正

### 核心禁止行为

以下行为在专利申请文件撰写中被严格禁止：

| 禁止行为 | 正确做法 |
|---------|---------|
| ❌ 使用"智能处理"、"自动分析"等空洞描述 | 说明具体技术手段，如"采用XX算法，通过XX方式处理XX数据" |
| ❌ 功能性限定而不说明具体技术手段 | 明确技术实现方式，包含算法/硬件/协议细节 |
| ❌ 堆砌技术术语而不说明作用 | 每个技术术语需说明其在方案中的作用 |
| ❌ 重复内容以凑字数 | 从不同角度描述，避免简单重复 |
| ❌ 虚构具体实验数据 | 使用定性描述或预期性描述，如"预计可实现..." |

### 撰写错误对照表

| 错误类型 | 错误示例 | 正确写法 |
|---------|---------|---------|
| 功能性限定 | "具有智能分析功能" | "基于LSTM神经网络，通过时间序列分析技术处理输入数据" |
| 模糊参数 | "采样频率约为1Hz" | "采样频率为1Hz±0.01Hz" |
| 宽泛领域 | "涉及计算机技术" | "属于计算机视觉技术领域中的目标检测子领域" |
| 商业宣传 | "全球领先的解决方案" | （删除，仅描述技术特征和效果） |
| 重复内容 | 在多个章节重复相同的技术描述 | 在不同章节从不同角度描述，避免简单重复 |

### 权利要求书常见错误

| 错误类型 | 错误示例 | 正确写法 |
|---------|---------|---------|
| 功能性限定（权利要求） | "所述分析模块用于智能分析数据" | "所述分析模块用于采用LSTM算法对数据进行时间序列分析" |
| 模糊参数（权利要求） | "采样频率约为1Hz" | "采样频率为1Hz±0.01Hz" |
| 超出说明书范围 | 说明书未提及的技术特征 | 确保权利要求的技术特征在说明书中有充分支持 |
| 前后矛盾 | 同一技术特征在不同权利要求中的描述不一致 | 确保全文术语和技术描述一致 |
| 引用错误 | "根据权利要求0所述的..." | 检查引用的权利要求编号是否正确 |
| 缺少技术手段 | "所述模块具有处理功能" | "所述模块采用XX算法对XX数据进行处理" |
