### 🔴 第一阶段：强制技术深度分析（新增）

**在开始撰写任何文档内容之前，必须完成以下分析：**

#### 步骤零：三要素一一对应检查（🔴 必须首先完成）

这是专利交底书的核心，必须先构建完整的对应关系，才能开始分析。

**1. 列出现有技术缺陷**

每个缺陷必须具体、技术化，不能是"缺乏机制"这种虚的描述：

| 缺陷编号 | 现有技术缺陷描述 | 技术化程度检查 |
|---------|----------------|--------------|
| D1 | 现有技术无法自动切换不同处理阶段的处理逻辑 | ✅ 具体技术问题 |
| D2 | 现有技术采用固定处理流程，导致不同类型内容无法得到差异化处理 | ✅ 包含原因和后果 |
| D3 | ... | ... |

**❌ 禁止示例**：
- "缺乏从创意到资产的转化机制" → 太虚，不具体
- "无法实现三维空间协同" → 不是技术问题
- "缺乏全链路机制" → 概念化描述

**✅ 正确示例**：
- "现有技术无法根据内容类型自动切换处理逻辑"
- "现有技术因为采用固定处理流程，导致处理效率低下"

**2. 列出本发明要解决的技术问题**

每个技术问题必须对应至少一个现有技术缺陷：

| 问题编号 | 技术问题描述 | 对应的缺陷编号 |
|---------|-------------|--------------|
| P1 | 如何实现根据内容类型自动切换处理逻辑 | D1 |
| P2 | 如何实现不同类型内容的差异化处理 | D2 |
| P3 | ... | ... |

**3. 列出创新点（技术特征）**

每个创新点必须是对应技术问题的解决方案，并且描述到可复现的粒度：

| 创新点编号 | 创新点描述（技术特征） | 技术特征粒度检查 | 对应的问题编号 |
|-----------|---------------------|----------------|--------------|
| I1 | 基于状态机的多阶段处理模块，包含 5 个状态：初始态、解析态、编码态、向量化态、完成态 | ✅ 具体到状态数量和名称 | P1 |
| I2 | 内容类型识别模块，根据文本特征将内容分类为 3 类：纯文本、结构化数据、混合数据 | ✅ 具体到分类数量和类型 | P2 |
| I3 | ... | ... | ... |

**❌ 禁止示例**：
- "三螺旋引擎" → 概念化命名，不是技术特征
- "9 大转化管道" → 太粗，没有具体说明
- "超级大脑" → 概念化描述

**✅ 正确示例**：
- "包含状态转换模块，维护 5 个状态..."
- "包含内容识别模块，采用 TF-IDF 算法..."
- "设置超时时间为 3600 秒"

**4. 列出技术效果**

每个技术效果必须是对应创新点的直接结果，不能是商业效果：

| 效果编号 | 技术效果描述 | 对应的创新点编号 | 是否技术效果 |
|---------|-------------|----------------|-----------|
| E1 | 支持不同阶段的自动切换，无需人工干预 | I1 | ✅ 是 |
| E2 | 不同类型内容能够得到差异化处理，处理准确率提升 20% | I2 | ✅ 是 |
| E3 | ... | ... | ... |

**❌ 禁止示例**：
- "实现认知、工程、经济三维协同" → 商业理念，不是技术效果
- "从碎片到资产的跃迁" → 商业价值，不是技术效果
- "提升市场竞争力" → 商业效果

**✅ 正确示例**：
- "实现自动切换，处理时间缩短 30%"
- "支持差异化处理，准确率提升 20%"
- "资源占用减少 50%"

**5. 一一对应关系验证**

生成后，必须验证每个创新点是否都有：
- 对应的现有技术缺陷
- 对应的技术问题
- 对应的技术效果

如果发现任何一个"创新点"没有对应的"缺陷"或"问题"或"效果"，必须：
- 要么删除这个"创新点"
- 要么补充对应的缺陷/问题/效果

---

#### 步骤一：技术原理深度剖析

**对输入的技术方案进行深度分析，回答以下问题：**

1. **核心技术原理是什么？**
   - 技术的物理/数学/计算机科学基础是什么？
   - 技术通过什么机制实现其功能？
   - 关键技术步骤之间的因果关系是什么？

2. **各组成部分的功能与实现方式是什么？**
   - 每个模块/组件负责什么功能？
   - 每个模块如何实现其功能？（算法/硬件/协议）
   - 模块之间如何交互？

3. **技术创新点体现在哪里？**
   - 与现有技术的本质区别是什么？
   - 创新是结构上的、算法上的、还是应用场景上的？
   - 为什么这个创新能解决现有技术的问题？

4. **技术实现的难点和解决方案是什么？**
   - 实现本技术面临什么技术挑战？
   - 如何克服这些挑战？
   - 关键技术参数的选择依据是什么？

**⚠️ 关键要求：**
- **禁止套用模板**：必须基于对技术的真实理解进行分析
- **禁止词语堆积**：每个技术术语必须有明确含义和作用
- **确保逻辑连贯**：前后描述必须自洽，不能出现矛盾

#### 步骤二：技术逻辑链条构建

**构建完整的技术实现逻辑链条：**

```markdown
输入 → 处理步骤1 → 处理步骤2 → ... → 输出
  ↓        ↓           ↓              ↓
[数据]  [技术手段1] [技术手段2]    [效果]
```

**对每个环节，必须说明：**
- 这个环节处理什么？
- 用什么技术手段处理？
- 为什么用这个手段？
- 这个环节的输入是什么？输出是什么？
- 这个环节与前后环节的关系是什么？

**⚠️ 禁止行为：**
- ❌ 跳过技术实现细节，只描述功能
- ❌ 使用"智能处理"、"自动分析"等空洞描述
- ❌ 堆砌技术术语而不说明其作用

#### 步骤三：技术深度自查

**在进入文档撰写前，完成以下自查：**

- [ ] 我能用通俗语言解释这个技术的工作原理吗？
- [ ] 我能说明每个技术模块的作用和实现方式吗？
- [ ] 我能说明技术实现的完整流程吗？
- [ ] 我能说明技术创新点在哪里吗？
- [ ] 我能说明技术参数的选择依据吗？

**如果任何一项为"否"，必须先深化技术理解，然后才能开始撰写。**
