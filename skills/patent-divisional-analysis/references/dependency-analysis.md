# 创新点依赖图构建方法

## 一、依赖关系类型

创新点之间可能存在以下关系：

| 关系类型 | 定义 | 图表示 | 专利影响 |
|---------|------|--------|---------|
| 强依赖 | B 必须使用 A 的输出才能实现 | A → B（实线） | 必须同组 |
| 弱依赖 | B 可以使用 A 的输出，但不必须 | A ⇢ B（虚线） | 倾向同组，可拆分 |
| 协同 | A 和 B 配合产生额外效果 | A ↔ B（双向虚线） | 倾向同组 |
| 独立 | A 和 B 无任何技术关联 | 无边 | 必须拆分 |
| 互斥 | A 和 B 是同一问题的替代方案 | A ⊥ B（标记） | 可同组（从属权保护）或不同组 |

---

## 二、关联分析流程

### Step 1：两两分析

对每对创新点 (A, B)，回答以下问题：

**Q1. 数据流依赖**
> A 的输出是否是 B 的输入？

| 回答 | 关系 |
|------|------|
| 是，B 必须用 A 的特定格式输出 | 强依赖 |
| 是，但 B 可以接收其他来源的数据 | 弱依赖 |
| 否 | 无数据依赖 |

**Q2. 功能依赖**
> B 是否调用了 A 提供的特定功能或接口？

| 回答 | 关系 |
|------|------|
| 是，B 调用 A 的核心算法/模块 | 强依赖 |
| 是，但 A 可被替代实现替换 | 弱依赖 |
| 否 | 无功能依赖 |

**Q3. 问题关联**
> A 和 B 是否服务于同一个技术问题？

| 回答 | 关系 |
|------|------|
| 是，解决同一问题的不同环节 | 协同 |
| 是，是同一问题的替代方案 | 互斥 |
| 否，解决不同问题 | 独立 |

**Q4. 技术特征共享**
> A 和 B 是否共享核心算法、数据结构、模型或处理流程？

| 回答 | 关系 |
|------|------|
| 共享核心算法/模型 | 强关联 |
| 共享数据结构但算法不同 | 弱关联 |
| 无共享 | 无关联 |

### Step 2：构建关联矩阵

将分析结果填入矩阵：

```
        A      B      C      D      E
A       -     强依赖  弱依赖  独立   协同
B      强依赖   -     独立   独立   独立
C      弱依赖  独立    -     协同   独立
D      独立   独立    协同    -     独立
E      协同   独立   独立   独立    -
```

### Step 3：绘制依赖图

基于矩阵，绘制 DAG（有向无环图）：

```
创新点A ──(强依赖)──→ 创新点B
   │
   └──(弱依赖)──→ 创新点C ←──(协同)──→ 创新点D

创新点E ←──(协同)──→ 创新点A
```

## 三、连通分量识别

### 算法

1. **只考虑强依赖和协同关系**，忽略弱依赖和独立关系
2. 使用深度优先搜索（DFS）找出所有连通分量
3. 每个连通分量作为一个候选分组

### 示例

```
图结构：
A -强依赖→ B
A -弱依赖→ C
C -协同→ D
E -协同→ A

Step 1: 忽略弱依赖边
剩余边：A→B（强），C↔D（协同），E↔A（协同）

Step 2: DFS 找连通分量
- 从 A 出发可达：A, B, E → 候选组1
- 从 C 出发可达：C, D → 候选组2

Step 3: 结果
候选组1：{A, B, E}（核心组）
候选组2：{C, D}（独立组）
```

## 四、关联性分析输出格式

对每组输出关联表：

```markdown
### 第N组关联表

| 创新点 | 层次定位 | 依赖关系 | 协同作用 | 与其他组的关系 |
|--------|---------|---------|---------|--------------|
| 创新点A | [层次] | -（基础） | 提供[能力]给B | 被第M组引用 |
| 创新点B | [层次] | 强依赖A | 实现[效果] | - |
| 创新点E | [层次] | 与A协同 | 增强[功能] | - |
```

### 组间关系描述

```markdown
### 组间关系

| 关系 | 描述 | 技术衔接点 |
|------|------|-----------|
| 第1组 → 第2组 | 第1组的输出是第2组的可选输入 | [具体接口/数据格式] |
| 第1组 ↔ 第3组 | 第3组是第1组的替代实现 | [可替换的模块] |
```
