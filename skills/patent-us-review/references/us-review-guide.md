## 一、适格性评审（35 U.S.C. § 101）

### 1.1 Alice 两步法判定流程

```
Step 1: 权利要求是否属于法定类别？
  ├── process / machine / manufacture / composition of matter → 进入 Step 2A
  └── 否（如自然规律、自然现象） → 不适格，评审结论：🔴 高风险

Step 2A: 是否指向法定例外（抽象思想）？
  ├── Prong 1: 是否列举了法定例外？
  │   ├── 抽象思想分组：
  │   │   • 数学概念（公式、计算、组织分析）
  │   │   • 人脑执行的心理过程（观察、评估、判断）  ← AI 最高频落入点
  │   │   • 组织人类活动的方法（商业实践、法律规则）
  │   │   • 基本经济实践（对冲、保险、风险管理）
  │   │
  │   └── Prong 2: 即使包含法定例外，是否将其融入了实际应用？
  │       ├── 改进了计算机内部运行（如数据处理速度、存储效率）
  │       ├── 改进了其他技术领域（如医学影像、自动控制）
  │       └── 对例外本身添加了有意义的技术限定
  │
  └── 如果 Prong 2 通过 → 适格，进入 Step 2B 为形式确认
      如果 Prong 2 未通过 → 进入 Step 2B 寻找 inventive concept

Step 2B: 是否包含"发明概念"（inventive concept）？
  ├── 权利要求元素单独或组合是否超越"well-understood, routine, conventional"
  ├── 通用计算机 + 通用算法 = 不够
  ├── 特定技术改进 + 非常规实现 = 可能足够
  └── 整体考量，不可忽略权利要求中的所有限定
```

### 1.2 AI 领域适格性速判表

| 权利要求模式 | 风险 | 典型判定 | 原因 |
|-------------|------|---------|------|
| "使用[AI模型]处理[数据]以获得[结果]" | 🔴 | 不适格 | 数学概念 + 心理过程 + 通用计算机执行 |
| "使用[AI模型]改进[特定技术领域]的方法" | 🟡 | 取决于限定深度 | 需要证明改进的是技术本身，而非仅应用技术 |
| "改进计算机内部运行的 ML 训练方法" | 🟢 | 适格 | 属于"improvement to computer functionality" |
| "基于[特定网络结构]的[具体技术问题]解决方案" | 🟢 | 适格 | 融入了特定技术应用的限定 |
| "使用神经网络进行分类/预测/识别" | 🔴 | 不适格 | 数学概念，缺少实际应用限定 |
| "嵌入硬件的 AI 控制系统" | 🟢 | 适格 | machine 类别 + 特定技术改进 |

### 1.3 高频否决话术与反驳方向

| 审查员典型否决话术 | 反驳方向 |
|-------------------|---------|
| "权利要求仅是数学算法 + 通用计算机执行" | 指出权利要求包含改进计算机内部功能的具体技术手段 |
| "使用神经网络处理数据属于心理过程" | 论证权利要求不是人脑能执行的过程（涉及大规模矩阵运算等） |
| "所有元素均为常规的" | 列举非常规元素：特定网络架构设计、非标准的训练策略、自定义损失函数等 |
| "权利要求仅将抽象思想应用于通用计算机" | 论证"特定机器或转换"（machine-or-transformation test）的满足情况 |

### 1.4 规避 101 风险的撰写建议

1. **在独立权利要求中体现"技术改进"**：不是"使用 AI 做了什么"，而是"AI 如何改进了技术"
2. **避免纯功能性描述**："利用 AI 模型分析数据" → "通过[具体网络结构]对[特定格式数据]执行[具体操作]，以改进[技术指标]"
3. **将 AI 方法锚定到具体应用场景**：权利要求应反映 AI 方法如何解决特定技术问题，而非通用 AI 流程
4. **强调非常规的技术手段**：如果训练方法、网络架构或数据处理流程有创新，应在权利要求中体现

## 二、新颖性评审（35 U.S.C. § 102）

### 2.1 关键规则

| 规则 | 说明 |
|------|------|
| 先申请制（AIA） | 2013年3月16日后适用先申请制 |
| 102(a) 公开 | 在有效申请日前已被专利/印刷出版物/公开使用/销售 |
| 102(b)(1) 宽限期 | 发明人本人或源自发明人的公开，1年内不构成先行技术 |
| 单篇对比原则 | 新颖性判断只能用**单篇**先行技术，不允许组合 |
| 隐含公开 | 对比文件无需逐字公开，隐含内容也算 |

### 2.2 AI 领域特殊关注点

| 公开形式 | 是否构成 102(a) 公开 | 评审关注点 |
|---------|---------------------|-----------|
| arXiv 预印本 | ✅ 是 | 公开日期以提交/发布日期为准 |
| GitHub 开源代码 | ✅ 是（如公开可访问） | 首次 commit 的公开日期 |
| 公开数据集 | ⚠️ 取决于情况 | 数据集本身通常不公开"方法"，但可能隐含技术方案 |
| 学术会议演示 | ✅ 是 | 会议日期为准，非论文集出版日期 |
| 学术论文 | ✅ 是 | 优先权日前公开即构成先行技术 |
| 内部测试/实验 | ❌ 否（如未公开） | 需确认确实未向公众披露 |

### 2.3 新颖性分析检查点

```
对于每项权利要求：
1. 列出全部技术特征
2. 确认是否存在单篇先行技术公开所有特征
3. 检查宽限期（102(b)(1)）是否适用
4. 评估隐含公开的风险
5. 输出：是否存在新颖性风险 → 风险等级 + 理由
```

## 三、非显而易见性评审（35 U.S.C. § 103）

### 3.1 Graham 四因素分析

```
因素1：确定现有技术的范围和内容
  → 识别最接近的先行技术（D1）

因素2：确定权利要求与现有技术的差异
  → 列出区别技术特征

因素3：确定差异所属技术领域的普通技术水平
  → AI 领域的 PHOSITA 标准通常较高（能使用标准框架/工具）

因素4：评估差异的显而易见性
  → 区别特征对 PHOSITA 是否显而易见？
  → 是否有技术启示（teaching/suggestion/motivation）将现有技术组合？
```

### 3.2 AI 领域常见显而易见性指控与反驳

| 指控模式 | 审查员逻辑 | 反驳方向 |
|---------|-----------|---------|
| "仅是已知 ML 算法的常规应用" | 将已知模型应用于新数据是显而易见的 | 论证应用中涉及的技术问题超出了常规（如数据特性需要新的预处理/特征工程） |
| "组合现有技术是显而易见的" | D1 + D2 的组合对 PHOSITA 来说是自然选择 | 论证结合障碍（D1 和 D2 存在技术矛盾）或无结合启示 |
| "参数优化是常规实验" | 调参是本领域技术人员的常规操作 | 论证参数的非常规选择产生了预料不到的效果 |
| "使用更大数据集训练是显而易见的" | 增加训练数据是常规手段 | 论证数据收集/标注/增强方法本身有技术创新 |

### 3.3 支持非显而易见性的有力论据

- **预料不到的技术效果**：性能提升幅度超出合理预期
- **克服技术偏见**：与领域内普遍认知相反的方法
- **长期的未解决需求**：该技术问题长期存在但无人解决
- **商业成功**：由技术特征直接导致的商业成功（辅助证据）
- **他人失败/未成功**：其他人尝试过但未能解决

## 四、充分公开与确定性评审（35 U.S.C. § 112）

### 4.1 112(a) 充分公开检查点

| 检查项 | 通过标准 | 常见问题 |
|-------|---------|---------|
| 训练数据描述 | 数据类型、来源、规模、标注方式可实施 | "大量训练数据"无具体说明 |
| 模型结构 | 层数、节点、连接方式描述充分 | "神经网络"无架构细节 |
| 超参数 | 范围明确，无需过度实验 | "适当的学习率"无范围 |
| 训练方法 | 损失函数、优化器、训练策略描述完整 | "训练模型"无训练过程 |
| 技术效果可再现 | 本领域技术人员按说明可实施 | 需要创造性实验才能实施 |

**Enablement 判定标准**：本领域技术人员能否**不需要过度实验（undue experimentation）**即可实施发明。

### 4.2 112(b) 模糊术语清单

| 高风险术语 | 问题 | 建议替换 |
|-----------|------|---------|
| "AI 模型" / "人工智能模型" | 未限定模型类型 | "卷积神经网络"/"注意力机制模型"等具体类型 |
| "智能分析" / "智能处理" | 纯功能性描述 | 具体处理步骤和算法 |
| "自动" / "智能" | 无技术含义 | 描述触发的条件和执行的具体操作 |
| "适当阈值" / "预设条件" | 范围不确定 | 具体数值或明确确定方法 |
| "等多种方式" | 开放式列举导致不确定 | 限定为具体的若干种方式 |
| "所述模块" | 模块边界不清 | 明确模块的输入、输出和处理逻辑 |

### 4.3 112(f) Means-plus-function 风险

当权利要求使用 "means for [功能]" 或类似功能性描述时，适用 112(f)：

- **风险**：权利要求的范围被限定为说明书中描述的对应结构**及其等价物**
- **AI 领域高危写法**："means for analyzing data"、"means for processing"、"means for learning"
- **规避方式**：用具体结构/算法替代 "means for" + 功能性描述
- **评审检查**：权利要求中是否出现 "means for" / "configured to" + 纯功能性描述

## 五、PCT 国际路径快速检查

### 5.1 路径选择

| 路径 | 适用场景 | 关键期限 |
|------|---------|---------|
| 巴黎公约 → 美国（直接） | 仅需美国保护，时间紧迫 | 中国申请日后 12 个月内提交美国申请 |
| PCT → 美国国家阶段 | 需要多国布局，争取评估时间 | 优先权日起 30 个月内进入美国国家阶段 |
| PCT → 美国 Continuation | 需要灵活调整权利要求范围 | 国家阶段进入后可提交 Continuation 申请 |

### 5.2 PCT 对美国评审的影响

| PCT 产物 | 对美国审查的影响 |
|----------|----------------|
| 国际检索报告（ISR） | ISR 引用的先行技术将在美国审查中被审查员重点参考 |
| 国际初步审查报告（IPER） | IPER 结论（尤其负面）可能影响美国审查员的初始倾向 |
| Written Opinion | 与 ISR 同步发出，其关于新颖性/创造性的意见具有参考价值 |
| Article 19 修改 | 国际阶段修改权利要求的机会，但不会影响国际检索报告 |
| Article 28/41 修改 | 进入国家阶段时修改权利要求的机会 |

### 5.3 关键时间节点

```
中国申请日（优先权日）
  │
  ├── 12个月 → 巴黎公约路径截止 / PCT 申请截止
  │
  ├── 16个月 → PCT 国际检索报告（ISR）发出
  │
  ├── 18个月 → 国际公开
  │               │
  │               └── Article 19 修改截止（国际公开后2个月内）
  │
  ├── 22个月 → 国际初步审查要求截止（如需）
  │
  ├── 28个月 → 国际初步审查报告（IPER）发出（如要求了初步审查）
  │
  └── 30个月 → 美国国家阶段进入截止
```
