# 分案布局分析技能

## 定位

本 Skill 解决的核心问题：**一个技术方案中有多个创新点，应该作为一件申请还是多件申请？每件申请怎么保护最优？**

与 `patent-innovation-splitter` 的区别：
- `patent-innovation-splitter`：**识别和切分**创新点（上游）
- `patent-divisional-analysis`（本 Skill）：**决策和布局**分案策略（下游）

## 输入

| 输入类型 | 说明 | 必要性 |
|---------|------|--------|
| 交底书/技术方案 | 包含多个技术方向的完整技术文档 | 必需 |
| 创新评估报告 | 已有的创新性评估结果 | 可选，有助于更准确的判断 |
| 创新点切分结果 | `patent-innovation-splitter` 的输出 | 可选，已切分好则直接用 |

## 输出

分案布局方案（Markdown），包含：

```markdown
# 分案布局方案

## 一、技术方案概览
- 技术领域
- 核心技术方向数：X 个
- 创新点总数：X 个

## 二、创新度分析
| 技术方向 | 创新度等级 | 授权可能性 | 说明 |
|---------|----------|----------|------|
| 方向A | 高 | 高 | ... |
| 方向B | 中 | 中 | ... |

## 三、单一性分析
- 各技术方向之间是否共享特定技术特征
- 是否属于同一总的发明构思
- 结论：[可以合案 / 需要分案 / 部分可合案]

## 四、分案建议
### 案件1（主案/母案）
- 覆盖范围：[核心技术方向]
- 独立权利要求方向：[方法/系统]
- 创新度：[高/中]
- 授权可能性评估：[高/中/低]

### 案件2（分案）
- 覆盖范围：[特定技术方向]
- 与案件1的关系：[共享XX技术特征 / 依赖案件1的XX]
- 独立权利要求方向：[方法/系统/设备]

### ...（更多分案）

## 五、保护策略建议
| 案件 | 策略 | 理由 |
|------|------|------|
| 案件1 | [作为从权 / 独立撰写] | ... |
| 案件2 | [作为从权 / 独立撰写] | ... |

## 六、权利要求布局建议
### 案件1 权利要求布局
- 独权1（方法侧）：覆盖XX流程
- 独权2（系统侧）：覆盖XX系统
- 从权3-5：细化XX具体实现
- 从权6-8：覆盖XX应用场景

### 案件2 权利要求布局
...

## 七、实施路径
1. 先申请案件X（核心保护）
2. 再申请案件Y（外围保护）
3. 分案时间节点建议
```

## 执行流程

### 阶段 1：准备

1. 读取 `knowledge/references/divisional-standards.md` — 分案/单一性判断标准
2. 读取输入的交底书/技术方案
3. 如有创新评估报告或切分结果，一并读取

### 阶段 2：技术方案解构

分析输入文档，提取以下信息：

| 提取维度 | 说明 |
|---------|------|
| 技术方向 | 方案涉及哪些独立的技术方向 |
| 创新点清单 | 每个技术方向包含哪些创新点 |
| 技术问题 | 每个创新点解决什么技术问题 |
| 技术特征 | 每个创新点的核心技术特征 |
| 技术效果 | 每个创新点带来的技术效果 |
| 关联关系 | 创新点之间的依赖/协同关系 |

### 阶段 3：创新度评估

对每个技术方向独立评估创新度：

| 评估维度 | 评估要点 |
|---------|---------|
| 新颖性 | 该方向的技术特征在现有技术中是否已有 |
| 创造性 | 是否有技术启示使本领域技术人员容易想到 |
| 技术贡献度 | 对整个方案的贡献大小 |
| 独立保护价值 | 单独保护的商业/技术意义 |

输出每个技术方向的创新度等级：

| 等级 | 标准 | 建议 |
|------|------|------|
| **高** | 明显区别于现有技术，技术效果显著 | 独立撰写，核心专利 |
| **中** | 有一定创新，但与现有技术有部分重叠 | 可独立或作为从权，视保护需求 |
| **低** | 基于公知技术的常规优化 | 建议作为从权或放入说明书 |

### 阶段 4：单一性分析

按 `divisional-standards.md` 中的判断方法：

1. **确定每个技术方向的特定技术特征**
2. **两两比较**是否存在相同或相应的特定技术特征
3. **判断单一性**：
   - 所有方向共享特定技术特征 → 可以合案
   - 部分共享 → 部分可合案
   - 各自独立 → 需要分案

### 阶段 5：分案策略决策

基于创新度评估 + 单一性分析，给出分案建议：

#### 决策矩阵

| 条件 | 建议 |
|------|------|
| 所有方向创新度高 + 有单一性 | 合案申请，多组从权 |
| 所有方向创新度高 + 无单一性 | 分案申请 |
| 部分高+部分低 + 有单一性 | 合案，高的放独权，低的放从权 |
| 部分高+部分低 + 无单一性 | 高的方向分案，低的放入说明书 |
| 全部低 | 不建议申请，或完善技术方案 |

#### 从权 vs 独立撰写判断

| 因素 | 倾向从权 | 倾向独立撰写 |
|------|---------|------------|
| 创新度 | 与主案相近，是细化 | 独立创新，与主案平行 |
| 技术关联 | 与主案共享核心技术特征 | 有独立的特定技术特征 |
| 保护需求 | 只需覆盖主案特定实现 | 需要独立保护范围 |
| 审查风险容忍度 | 低（担心主案被驳回牵连） | 高（分案互不影响） |

### 阶段 6：输出布局方案

按输出模板生成分案布局方案文档。

## 质量检查

| 检查项 | 标准 |
|--------|------|
| 技术方向识别 | 所有关键技术方向都被识别 |
| 创新度评估合理性 | 评估有依据，不是主观臆断 |
| 单一性判断准确性 | 引用了具体的法条和判断标准 |
| 分案建议可操作性 | 每个建议都有明确的理由 |
| 保护策略实用性 | 考虑了成本、风险、商业价值 |
