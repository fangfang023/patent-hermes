# 权利要求书自检规则

本文件定义阶段1.5（权利要求书自检）的详细审查规则。审查员角色切换、7项检查清单的执行方法、判定标准、修正示例。

## 角色切换要求

阶段1.5开始时，必须从"撰写者"切换为"专利审查员"角色：

- **审查员视角**：以挑剔、质疑的眼光审视权利要求书，目标是找出漏洞，而非验证正确性
- **不依赖 context 记忆**：从文件重新读取权利要求书，避免撰写过程中的思维惯性
- **逐条回答**：7项检查必须逐条输出结果，不可跳过或合并

---

## 7项结构化检查清单

### 检查1：独立权利要求是否只包含必要技术特征

**检查方法**：对每个独立权利要求的每个技术特征，问：
> "删掉这个特征，发明还能解决核心技术问题吗？"
- 能解决 → 非必要特征，应下放到从属权利要求
- 不能解决 → 必要特征，保留

**通过标准**：独立权利要求中无冗余限定，每个特征都是解决核心技术问题所必需的。

**修正示例**：

```
❌ 独立权利要求1：
一种数据处理方法，包括：
步骤A：采集用户行为数据；
步骤B：采用Transformer模型提取特征；     ← 非必要（换LSTM也能解决）
步骤C：基于特征计算相似度；
步骤D：输出推荐结果。

✅ 修正后：
独立权利要求1：
一种数据处理方法，包括：
步骤A：采集用户行为数据；
步骤B：采用深度学习模型提取特征；         ← 上位概括，必要技术手段
步骤C：基于特征计算相似度；
步骤D：输出推荐结果。

（"Transformer模型"下放到从属权利要求）
```

---

### 检查2：独立权利要求是否过窄

**检查方法**：扫描独立权利要求中是否出现以下内容：

| 过窄信号 | 示例 | 应替换为 |
|---------|------|---------|
| 具体算法名称 | "BERT模型"、"LSTM神经网络" | "预训练语言模型"、"时序预测模型" |
| 具体数值参数 | "采样频率为1Hz" | "预设采样频率" |
| 具体型号 | "型号为XYZ的传感器" | "传感器" |
| 具体协议名称 | "HTTP协议" | "通信协议" |

**通过标准**：独立权利要求中无具体算法名称、具体数值、具体型号、具体协议。

---

### 检查3：是否存在纯功能性限定

**检查方法**：逐句扫描独立权利要求，找出所有"用于…的模块/装置/单元/步骤"，确认其后是否包含**实现该功能的技术手段**。

**判定规则**：
- "所述分析模块用于智能分析数据" → ❌ 纯功能性限定，无技术手段
- "所述分析模块用于采用时序预测模型对数据进行分析" → ✅ 功能+技术手段

**通过标准**：每个功能性描述都附带了"如何实现"的具体技术手段。

---

### 检查4：从属权利要求是否构成防御纵深

**检查方法**：

1. **检查引用结构**：绘制引用关系图，判断是平铺还是树状
2. **检查覆盖范围**：核心特征是否有多种实现方式分别保护

**引用结构判定**：

```
平铺结构（❌ 防御不足）：
权2 → 引权1
权3 → 引权1
权4 → 引权1
（所有从属权都直接引用权1，无层次）

树状结构（✅ 防御纵深）：
权2 → 引权1（限定：向量相似度匹配）
  权3 → 引权2（限定：余弦相似度）
  权4 → 引权2（限定：欧氏距离）
权5 → 引权1（限定：预设采样频率范围）
```

**通过标准**：
- 从属权利要求形成≥2层深度的树状引用
- 至少有一个核心特征被2种以上替代实现方式分别保护

---

### 检查5：术语一致性

**检查方法**：对比所有权利要求中对同一技术概念的表述。

**常见不一致**：

| 权利要求1 | 权利要求3 | 问题 |
|----------|----------|------|
| "用户行为数据" | "用户操作数据" | 同一概念不同术语 |
| "特征提取模块" | "特征获取单元" | 同一模块不同名称 |
| "相似度计算" | "匹配度计算" | 同一操作不同表述 |

**通过标准**：全文同一技术概念使用统一术语。

---

### 检查6：从属权利要求的附加特征是否与引用对象关联

**检查方法**：每条从属权利要求问：
> "这个附加特征是否是对所引用权利要求的进一步限定？是否引入了全新的、无关联的技术特征？"

**判定规则**：
- 从属权的附加特征与所引用权利要求存在直接技术关联 → ✅
- 从属权引入了与引用对象无关的新技术特征 → ❌

**修正方式**：
- 删除无关特征
- 如果脱节的从属权本身有价值，改写为新的独立权利要求（需满足单一性）

---

### 检查7：权利要求总数

**通过标准**：10-15条。

- 不足10条 → 补充从属权利要求（增加替代实现方式、优选参数等）
- 超过15条 → 检查是否有冗余从属权，合并内容相近的条款

---

## 自检流程

```
初始化: check_round = 1, max_rounds = 3

1. 从文件读取: ./generated_docs/权利要求书_[发明名称].md
2. 切换为审查员角色
3. 逐条执行7项检查，输出检查结果表
4. IF 7项全部通过 → 自检通过，进入阶段2
   ELSE → 执行修正，重新写入文件，check_round += 1
     IF check_round > max_rounds → 强制进入阶段2
     ELSE → 回到步骤1
5. 输出自检结果摘要
```
