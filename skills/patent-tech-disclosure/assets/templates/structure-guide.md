## 一、技术术语使用规范

### 1.1 数学公式格式规范

> **详细规范请参考**：`../SKILL.md` 中的"原则六：数学公式LaTeX格式规范原则"

**所有数学公式必须使用LaTeX格式（`$...$` 内联 或 `$$...$$` 块级），禁止使用Unicode纯文本符号。**

| 数学元素 | ❌ Unicode文本 | ✅ LaTeX格式 |
|---------|--------------|-------------|
| 上标 | `x^2`, `^(256×128)` | `$x^2$`, `$^{256 \times 128}$` |
| 下标 | `W_MT`, `x_i` | `$W_{MT}$`, `$x_i$` |
| 希腊字母 | `α, β, σ, π` | `$\alpha, \beta, \sigma, \pi$` |
| 集合符号 | `∈ R` | `$\in \mathbb{R}$` |
| 分数 | `a/b`, `1/2` | `$\frac{a}{b}$`, `$\frac{1}{2}$` |
| 根号 | `√x`, `√(a+b)` | `$\sqrt{x}$`, `$\sqrt{a+b}$` |
| 求和 | `Σ`, `Σ(i=1 to n)` | `$\sum_{i=1}^{n}$` |
| 积分 | `∫`, `∫(0 to ∞)` | `$\int_{0}^{\infty}$` |
| 矩阵 | `[a b; c d]` | `$\begin{pmatrix} a & b \\ c & d \end{pmatrix}$` |
| 点乘 | `W·M` | `$W \cdot M$` |

**DOCX转换**：`pandoc input.md -o output.docx --mathml`

### 1.2 允许使用的术语（具体明确）

- **具体技术名称**：如"卷积神经网络"、"支持向量机"、"BERT模型"、"YOLO检测器"
- **具体算法名称**：如"A*算法"、"Dijkstra算法"、"梯度下降法"、"K-means聚类"
- **具体框架/工具**：如"TensorFlow"、"PyTorch"、"Neo4j"、"FAISS向量库"
- **具体协议/标准**：如"HTTP/2"、"WebSocket"、"MQTT协议"、"OOXML格式"

### 禁止使用的术语（必须说明具体实现）

| 禁止术语 | 必须说明 |
|---------|----------|
| ❌ "智能处理" | 什么算法、如何处理、处理规则 |
| ❌ "自动分析" | 分析规则、决策逻辑、判断标准 |
| ❌ "先进技术" | 具体是什么技术、先进在哪里 |
| ❌ "高效算法" | 算法名称、时间复杂度、为什么高效 |
| ❌ "大数据分析" | 数据规模、分析方法、处理流程 |
| ❌ "深度理解" | 理解方式、模型架构、训练方法 |
| ❌ "精准识别" | 识别方法、准确率、误报率 |

### 概念堆砌检测规则

如果在一段描述中出现超过3个技术术语且没有说明其作用，则判定为"概念堆砌"，需要重写。

### 示例对比

```
❌ 错误示例：
本系统采用先进的AI技术，通过智能分析和深度理解，实现高效的数据处理。

✅ 正确示例：
本系统采用BERT预训练模型（12层Transformer架构），通过语义相似度计算
（余弦相似度阈值0.85）和实体识别（BERT-NER模型，F1分数0.92），实现文本
数据的自动分类，处理速度达到1000条/秒。
```

## 二、优秀写作规范

### 2.1 背景技术：逐一列举 + 逐一缺陷分析 + 深度描述

**⚠️ 重要：只保留1-2个最核心的技术问题，避免问题堆积！**

- 不要笼统地说"现有技术有问题"
- 每种现有技术单独编号分析
- 先描述技术方案，再分析缺陷及其产生原因

**深度描述要求（每个现有技术至少300字）：**

| 检查项 | 深度要求 | 最低字数 |
|-------|---------|---------|
| 技术原理 | 说明技术基于什么原理工作 | 50字 |
| 实现方式 | 说明技术具体如何实现 | 80字 |
| 关键组件 | 说明技术包含哪些关键部分 | 60字 |
| 缺陷描述 | 具体指出技术上的不足 | 50字 |
| 原因分析 | 分析为什么会出现这个缺陷 | 60字 |

**现有技术深度描述模板：**

```
[现有技术名称]是一种[技术分类]，其核心原理是通过[技术原理]来实现[功能]。

具体实现上，该技术通常采用[实现方式1]和[实现方式2]。首先，[步骤1描述]；
然后，[步骤2描述]；最后，[步骤3描述]。关键技术组件包括[组件1]、[组件2]和
[组件3]，它们分别负责[功能1]、[功能2]和[功能3]。

然而，该技术在[具体场景]下存在明显缺陷。具体表现为：[具体缺陷描述]。
这个问题的根本原因在于[原因分析]，导致[影响结果]。
```

**示例：**

```
1. 知识图谱（KG）技术：能够构建学科知识点的关联网络，
   但图谱本身是静态的，缺乏对知识深层语义的理解...

2. 认知诊断模型（CDM）：通过学生答题的对错推断知识点掌握概率，
   但诊断结果模糊（如"掌握概率0.3"），无法利用学生具体的
   解题过程和答案内容...
```

### 2.2 技术方案：对比式描述句式

- 每个创新点先说明"现有技术中...的情况"
- 再说明"本发明提出/采用...的方法"

**示例：**

```
现有技术中知识图谱的构建多为单向静态过程，
本发明提出知识图谱与学情数据的双向迭代机制...
```

### 2.3 技术方案：步骤化编号 + 多层次结构

- 使用"步骤一、步骤二、步骤三"清晰编号
- 每个步骤下有子要点，用项目符号（•）组织

**示例：**

```
步骤一：AI深度解析
• 页面级解析：识别文档的总页数、页面顺序...
• 元素级解析：识别每页中的各种元素...
• 关系推断：AI模型进一步分析元素间的隐含关系...
```

### 2.4 有益效果：编号列表 + 与技术方案对应

- 使用编号（1、2、3...）列表
- 每个效果说明其技术依据（因为采用了某技术特征）
- 与技术方案中的创新点形成对应关系

### 2.5 用具体数值/示例支撑技术描述

- 用具体数值说明技术实现（如"从0.6调整至0.8"）
- 用具体示例说明抽象概念
- 用公式或参数范围说明算法细节

### 2.6 每个创新点末尾有总结性语句

- 用一句话总结该创新点的技术意义
- 说明"此机制使...，区别于现有技术中..."

**示例：**

```
此机制使知识图谱从单纯的知识载体升级为融合教学反馈的
智能自适应系统，区别于现有技术中静态图谱的被动应用模式。
```

## 五、附图说明

**⚠️ 必须包含 Mermaid 代码附图（≥2幅）**

提供**可直接运行的 mermaid 代码**，图表类型与内容对应：

### 5.1 附图类型要求

根据技术方案特点，选择以下图表类型：

| 图表类型 | Mermaid 语法 | 适用场景 | 必需数量 |
|---------|-------------|----------|---------|
| 系统架构图 | `graph TD` | 展示整体系统组成、模块间关系 | 至少1幅 |
| 方法流程图 | `flowchart TB` | 展示算法执行流程、数据处理步骤 | 至少1幅 |
| 模块交互图 | `sequenceDiagram` | 展示各模块间的交互时序 | 可选 |
| 数据结构图 | `classDiagram` | 展示数据模型、类结构 | 可选 |
| 状态转移图 | `stateDiagram-v2` | 展示状态机、状态转换 | 可选 |

  ### 5.2 附图撰写规范                                      

  **⚠️  核心原则：专利代理人视角**

  读者是专利代理人（法律专业人士），不是技术专家。

  **图的作用是辅助理解：**
  - 突出核心关系，细节在文字中说明
  - 不要把算法细节、参数列表全部画在图里

  **每幅附图必须包含：**

  1. **图号和图名**：如"图1：系统整体架构图"
  2. **Mermaid 代码块**：使用 \`\`\`mermaid ... \`\`\` 包裹
  3. **图表说明**：简要描述图表展示的核心内容
