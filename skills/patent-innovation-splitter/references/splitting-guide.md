# 创新点切分规则与单一性判断标准

## 一、创新点识别标准

### 什么是独立的创新点？

一个创新点是一个**完整的技术贡献单元**，满足：
1. **独立解决至少一个技术问题**
2. **有明确的技术手段**（不是纯概念或功能描述）
3. **能产生可度量的技术效果**

### 创新点粒度判断

| 粒度 | 特征 | 处理方式 |
|------|------|---------|
| 过粗 | 一个"创新点"实际包含多个独立技术方案 | 拆分为多个创新点 |
| 合适 | 解决一个技术问题，有一个核心技术手段 | 保留为一个创新点 |
| 过细 | 只是某个技术手段的一个参数优化 | 合并到所属创新点 |

### 识别步骤

1. **通读全文**，标记所有描述"技术改进"的段落
2. **提取三要素**：对每个技术改进，提取"技术问题 → 技术手段 → 技术效果"
3. **独立性检验**：如果去掉某个技术改进，其他技术改进是否仍能独立存在？能独立存在 → 是独立创新点
4. **去重合并**：多个段落描述同一技术改进的不同方面 → 合并为一个创新点

## 二、单一性判断标准（依据《专利审查指南》）

### 单一性定义

一件发明或者实用新型专利申请应当**只有一个发明构思**。即属于一个总的发明构思的两项以上的发明或者实用新型，应当在**技术上相互关联**，包含一个或者多个**相同或者相应的特定技术特征**。

### "特定技术特征"的判断

特定技术特征 = 每一项发明作为整体，对现有技术做出**贡献的技术特征**。

**判断流程**：

```
Step 1: 确定每项发明的贡献点（区别于现有技术的特征）
    ↓
Step 2: 判断多个发明之间是否存在共同的贡献点
    ↓
Step 3: 如果存在 → 满足单一性；不存在 → 不满足单一性
```

### 单一性判断矩阵

| 情况 | 创新点A | 创新点B | 单一性 | 处理 |
|------|---------|---------|--------|------|
| 共享核心技术 | 新型编码算法A | 基于A的压缩方法 | 满足 | 同一专利 |
| 同一技术问题的不同方案 | 提高识别精度的方法X | 提高识别精度的方法Y | 看具体情况 | 如果X和Y共享技术特征则满足 |
| 完全独立 | 数据加密方法 | 界面渲染优化 | 不满足 | 必须拆分 |
| 上下游技术 | 数据采集方法A | 基于A的数据分析方法B | 看具体情况 | 如果B必须依赖A的特殊输出则满足 |

### 单一性检验清单

对每组创新点，逐项检查：

- [ ] 组内创新点是否共享至少一个技术特征？
- [ ] 共享的技术特征是否是"特定的"（对现有技术有贡献的）？
- [ ] 如果没有共享特征，是否解决同一个技术问题的不同方面？
- [ ] 每组是否只有一个核心的发明构思？

**通过标准**：以上至少两项为"是"。

## 三、切分触发条件

### 何时需要切分？

满足以下**任一**条件即应切分：

| 条件 | 说明 | 示例 |
|------|------|------|
| 独立创新点 > 3个 | 超过单一专利合理保护范围 | 一个方案包含5个独立创新点 |
| 跨多个技术问题 | 创新点服务于不同技术问题 | 部分创新点解决"精度"问题，部分解决"速度"问题 |
| 跨技术层次 | 创新点分布在不同架构层 | 数据层、算法层、应用层各有关键创新 |
| 独立权利要求 > 3组 | 难以合并为单一专利 | 需要多组独立权利要求保护不同方向 |

### 何时不切分？

| 条件 | 说明 |
|------|------|
| 独立创新点 ≤ 2个 | 可纳入同一专利 |
| 所有创新点强依赖 | 去掉任何一个，其他都无法实现 |
| 只有一个技术问题 | 所有创新点服务于同一核心问题 |

## 四、切分粒度控制

### 基本原则

- **每组 1-3 个创新点**：确保每份交底书聚焦，权利要求层次清晰
- **每组聚焦一个技术问题**：便于撰写独立权利要求
- **保持组间逻辑关系**：确保专利包的整体性

### 粒度调整规则

| 情况 | 规则 |
|------|------|
| 强依赖的创新点（A的输入= B的输出） | 必须在同一组 |
| 共享核心技术特征的创新点 | 倾向在同一组 |
| 解决同一问题的不同方案 | 可在同一组，通过从属权利要求分别保护 |
| 完全独立的创新点 | 必须拆分到不同组 |
| 上游-下游关系但不强依赖 | 可拆分，但标注关联 |
